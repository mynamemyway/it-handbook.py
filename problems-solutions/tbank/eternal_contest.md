## Problem 1: Расчет стоимости интернет-трафика

**Условие:**
У Кости есть тарифный план. За месяц он платит фиксированную стоимость **A** рублей, в которую включено **B** Мб интернет-трафика. Если Костя превышает этот лимит, то каждый бóльший Мб стоит ему **C** рублей. Известно, что в следующем месяце Костя планирует потратить **D** Мб трафика. Какова будет суммарная стоимость интернета?

**Входные данные:**
Четыре целых числа **A**, **B**, **C**, **D** (1 ≤ A, B, C, D ≤ 100), разделенные пробелом.

**Выходные данные:**
Одно целое число — общая стоимость интернет-трафика в рублях.

**Примеры:**
* Вход: `100 10 12 15` -> Выход: `160` (абонентская плата 100 + 5 лишних Мб по 12 рублей)
* Вход: `100 10 12 8` -> Выход: `100` (лимит не превышен)


```py
# A - стоимость тарифа в мес
# B - размер тарифа Мб в мес
# C - стоимость лишнего 1 Мб
# D - Мб потрачено в следующем мес
# Числа во входном файле разделены пробелами.
# Во сколько рублей обойдётся интернет-трафик в следующем месяце?

# Алгоритм: Прямой расчет (Арифметика)
# Обоснование: Задача решается одной формулой, ветвление (if) обрабатывает лимит.
# Сложность: O(1).

a, b, c, d = [int(n) for n in input().split()]

def get_amount(a, b, c, d):
    if d <= b:
        return a
    return a + ((d - b) * c)

print(get_amount(a, b, c, d))
```

## Problem 2: Минимальное количество разрезов рулета

**Условие:**
Необходимо разрезать рулет на N равных частей поперечными разрезами. За одно движение можно сложить уже отрезанные куски стопкой и разрезать их одновременно (если места разрезов совпадают). Какое минимальное число движений ножом потребуется?

**Входные данные:**
Одно натуральное число N (1 ≤ N ≤ 2 × 10⁹) — количество необходимых частей.

**Выходные данные:**
Одно целое число — минимальное количество разрезов.

**Примеры:**
* Вход: 6 -> Выход: 3 (разрезать на 2 части, сложить, сделать еще 2 разреза)
* Вход: 5 -> Выход: 3

```py
# Вариант 1: Оптимизация цикла (через битовые сдвиги или лаконичную математику)

# Алгоритм: Бинарный поиск по ответу (неявно) / Математика
# Обоснование: Каждый разрез удваивает количество частей.
# Сложность: O(log N).
# Рекомендация: Использование bit_length() (Вариант 2) — самый быстрый способ найти степень двойки.

n = int(input())
def get_cuts(n):
    cuts = 0
    while n > 1:
        # Формула (n + 1) // 2 заменяет весь твой if-else для округления вверх
        n = (n + 1) // 2
        cuts += 1
    return cuts

print(get_cuts(n))
```

Вариант 2: Высший пилотаж для собеседования — решение за **O(1)**
В Python у типа int есть встроенный метод .bit_length(), который возвращает количество бит, необходимых для представления числа в двоичной системе. Для любого **N > 1** минимальное число разрезов — это в точности длина двоичной записи числа **N - 1**.

```py
n = int(input())
def get_cuts_fast(n):
    if n <= 1:
        return 0
    return (n - 1).bit_length()

print(get_cuts_fast(n))
```

Почему это работает: Если **N = 6**, то **N - 1 = 5**. В двоичной системе **5 = 101_2** (3 бита). Ответ: 3. Если **N = 4**, то **N - 1 = 3 = 11_2** (2 бита). Ответ: 2. Время работы такого решения — **O(1)**, то есть константное.

## Problem 3: Оптимальный обход этажей

**Условие:**
Кате нужно посетить **n** сотрудников на разных этажах, перемещаясь между ними строго по лестнице (1 пролет = 1 минута). На старте Катя может бесплатно (за 0 минут) подняться на лифте на абсолютно любой этаж. Один особый сотрудник уйдет ровно через **t** минут. Кате обязательно нужно успеть к нему до его ухода. Какое минимальное количество лестничных пролетов ей придется пройти, чтобы посетить всех?

**Входные данные:**
* Первая строка: два числа **n** - количество сотрудников и **t** - время до ухода особого сотрудника (**2 <= n, t <= 100**).
* Вторая строка: **n** чисел — номера этажей сотрудников (в порядке возрастания, от -100 до 100).
* Третья строка: номер сотрудника по счету, который уйдет через t минут.

**Выходные данные:**
* Одно целое число — минимальное количество пройденных пролетов.

**Примеры:**
* Вход: `5 5` / `1 4 9 16 25` / `2` -> Выход: `24`
* Вход: `6 4` / `1 2 3 6 8 25` / `5` -> Выход: `31`

```py
# Алгоритм: Жадный алгоритм / Разбор случаев (Greedy)
# Обоснование: Нам не нужен BFS, так как структура этажей линейна.
# Сложность O(1).
# Сравниваем два варианта: пройти весь путь сразу или зайти к особому сотруднику и вернуться.

# Входные данные
n, t = [int(x) for x in input().split()]
flors = [int(x) for x in input().split()]
i = int(input()) - 1  # индекс этажа особого сотрудника

# Этаж уходящего сотрудника по индексу
special_flor = flors[i]

# Количество шагов между всеми сотрудниками
all_steps = flors[-1] - flors[0]

# Шаги от самого верхнего и самого нижнего этажей
# до особого сотрудника
steps_from_low = special_flor - flors[0]
steps_from_hight = flors[-1] - special_flor

# Если времени достаточно чтобы пройти от одного из крайних до особого
if t >= steps_from_low or t >= steps_from_hight:
    # Отправляем Катю по прямой после лифта
    steps = all_steps

else:
    # Длина отрезка А (steps_from_low)
    # Длина отрезка Б (steps_from_hight)
    # Длина всей дороги (all_steps)
    steps = min([steps_from_low + all_steps, steps_from_hight + all_steps])

print(steps)
```

## Problem 4: Максимальное увеличение суммы чисел

**Условие:**
На бумажке написано **n** чисел. Также у Кости есть возможность не больше, чем **k** раз, взять любое число с бумажки, после чего закрасить одну из старых цифр, а на ее месте написать новую произвольную цифру. На какое максимальное значение Костя сможет увеличить сумму всех чисел на листочке?

**Входные данные:**
* Первая строка: два целых числа **n** и **k** (1 ≤ n ≤ 1000, 1 ≤ k ≤ 10⁴) — количество чисел на бумажке и ограничение на число операций.
* Вторая строка: **n** чисел **a_i** (1 ≤ a_i ≤ 10⁹) — числа на бумажке.

**Выходные данные:**
* Одно число — максимальная разность между конечной и начальной суммой.
* *Важно:* Ответ может превышать вместимость 32-битного типа данных.

**Тест:**
Пример 1
Ввод
5  2
1  2  1  3  5

Вывод
16

Пример 2
Ввод
3  1
99  5  85

Вывод
10

**Замечание:**
* В первом примере Костя может изменить две единицы на две девятки, в результате чего сумма чисел увеличится на 16.
* Во втором примере Костя меняет число 85 на 95.
* В третьем примере можно ничего не менять.


```python
# Алгоритм: Жадный алгоритм (Greedy)
# Обоснование: Вычисляем "вес" (профит) от замены каждой цифры на 9 и выбираем K самых выгодных.
# Сложность: O(D log D), где D — общее количество цифр.

n, k = [int(i) for i in input().split()]
nums = input().split()

all_exchange = []

# Собираем прирост от замены всех цифр
for num in nums:
    length = len(num)
    # Раскладываем на цифру и индекс, считаем вес замены
    for idx, digit in enumerate(num):
        val = int(digit)
        if val < 9:
            weight = 10 ** (length - 1 - idx)
            gain = (9 - val) * weight
            all_exchange.append(gain)

# Ставим в начало самые выгодные замены
all_exchange.sort(reverse=True)

# Режем менее выгодные количеством допустимых замен
print(sum(all_exchange[:k]))
```

## Problem 5: Генерация тестов из одинаковых цифр

**Условие:**
Саше нужно сгенерировать тесты в виде натуральных чисел в диапазоне от **l** до **r** включительно. Особое требование: каждое число должно состоять из абсолютно одинаковых цифр (например: 7, 77, 999). Сколько различных тестов сможет создать Саша?

**Входные данные:**
* Единственная строка содержит два натуральных числа **l** и **r** (1 ≤ l ≤ r ≤ 10¹⁸) — границы диапазона.

**Выходные данные:**
* Одно целое число — количество подходящих чисел на отрезке [l, r].

**Примеры:**
* Вход: `4 7` -> Выход: `4` (подходят числа 4, 5, 6, 7)
* Вход: `10 100` -> Выход: `9` (подходят числа 11, 22, 33, 44, 55, 66, 77, 88, 99)

```py
# Алгоритм: Полный перебор (Brute-force / в лоб) / Математика
# Обоснование: Всего существует 9 * 18 = 162 таких чисел до 10^18.
# Проще сгенерировать их все и проверить вхождение в диапазон, чем вычислять формулой.
# Сложность: O(1)

l, r = [int(i) for i in input().split()]

# Все варианты тестов в допустимом диапазоне
# all_var = 18 * 9
#
# 1. Нужно каждое число от 1 до 9 как строку умножить на 9
# 2. Затем повторить это для числа 11, затем для 111 и так с 18 числами
nums = []

for i in range(1, 10):
    for n in range(1, 19):
        num = int(str(i) * n)
        if l <= num <= r:
            nums.append(num)

print(len(nums))
```

## Problem 6: Выстраивание шеренги по чётности позиций

**Условие:**
На физкультуре происходит разбиение по двум командам. Ребята выстроены в шеренгу, у каждого из них есть свой рост **a_i**. Разбиение по командам произойдет по принципу «четный-нечетный» — все школьники с четным ростом отправляются в одну команду, а нечетные — в другую.

В отличие от привычного урока, ребята не выстроились по росту. Вместо привычного порядка они встали случайно. Теперь физрук Яша смотрит на шеренгу и думает — может ли ровно одна пара учеников поменяться местами так, чтобы команды оказались такими же, как и по принципу «первый-второй». Иначе говоря, он хочет получить такой порядок, при котором все ученики с четным ростом стоят на четных позициях, а с нечетным — на нечетных.

Помогите Яше найти нужную замену.

**Условие упрощенное:**
Школьники выстроены в шеренгу из **n** человек, у каждого задан рост. Позиции школьников нумеруются с 1 до **n**. Физрук хочет, чтобы школьники с чётным ростом стояли строго на чётных позициях, а с нечётным — строго на нечётных. Можно ли выбрать **ровно одну пару** школьников и поменять их местами так, чтобы это условие выполнилось для всей шеренги?

**Входные данные:**
* Первая строка: число **n** (2 ≤ n ≤ 1000) — количество учеников в шеренге.
* Вторая строка: **n** натуральных чисел **a_i** (1 ≤ a_i ≤ 10⁹) — рост учеников.

**Выходные данные:**
* В единственной строке выведите **i** и **j** — номера элементов, которые нужно поменять местами, чтобы добиться заданного условия (1 ≤ i, j ≤ n, i ≠ j). Если ответов несколько — разрешается вывести любой.
* Если не существует способа поменять два элемента местами — выведите `-1 -1`.

**Примеры:**
Пример 1
Ввод
4
2 1 4 6

Вывод
-1 -1

Пример 2
Ввод
2
1 2

Вывод
-1 -1

Пример 3
Ввод
2
2 1

Вывод
1 2

**Замечания:**
* В первом примере хотя бы один ученик с четным ростом будет стоять на нечетной позиции.
* Во втором тесте замена приведет к неправильному состоянию.
* В третьем тесте из условия замена приведет шеренгу к валидному состоянию.

```python
# Алгоритм: Линейное сканирование (Linear Scan)
# Обоснование: Мы проходим по списку один раз, чтобы найти индексы с нарушенной четностью.
# Сложность O(N).
# Сопоставить чётность роста с чётностью индекса (1)

n = int(input())
nums = [int(num) for num in input().split()]

even_on_not_even = []
not_even_on_even = []

for idx, num in enumerate(nums):
    if idx % 2 != 0 and num % 2 != 0:
        not_even_on_even.append(idx + 1)
    elif idx % 2 == 0 and num % 2 == 0:
        even_on_not_even.append(idx + 1)

# Кейс 1: есть по одному нарушителю
if len(even_on_not_even) == 1 and len(not_even_on_even) == 1:
    res = [even_on_not_even[0], not_even_on_even[0]]

# Кейс 2: нарушителей нет
elif len(even_on_not_even) == 0 and len(not_even_on_even) == 0 and n > 2:
    res = [1, 3]

# Кейс 3: нет решения
else:
    res = [-1, -1]

print(*res)
```

## Problem 7: Тайный Санта и единая цепочка

**Оригинальное условие:**
В школе перед Новым Годом устраивают игру в Тайного Санту. Каждому ученику **i** выдается ученик **a_i**, которому он должен подарить подарок.

Костя, как администратор игры, определил каждому школьнику свое число **a_i**. Но потом его коллега Маша спросила: «А правда ли, что если начать цепочку подарков от школьника 1 к школьнику **a_1**, потом к **a_(a_1)** и так далее, то цепочка замкнется на школьнике 1, после того как задействует всех остальных учеников ровно по одному разу?» (То есть все ученики должны образовать один большой замкнутый цикл).

Костя не знает, правда это или нет, но он собирается изменить **ровно одно** число **a_i**, чтобы получить конфигурацию, которая устроит Машу. Помогите ему с этим: найдите номер ученика **x**, у которого нужно изменить цель, и новое значение **y**.

**Упрощённое понимание логики:**
* **Суть игры:** Есть `n` человек. Каждый указывает пальцем на того, кому дарит подарок.
* **Что хочет Маша:** Если мы начнём с 1-го человека и пойдём по цепочке (первый передаёт второму, второй третьему и т.д.), то подарок должен обойти абсолютно всех людей по одному разу и в самом конце вернуться к 1-му. Образуется один большой замкнутый круг.
* **Что есть у Кости:** Сейчас люди указывают случайно. Кто-то может дарить подарок сам себе, кому-то вообще ничего не дарят, а где-то образовались изолированные кружки (например, 1 и 2 дарят друг другу, а 3 и 4 — друг другу).
* **Задача:** Косте разрешено подойти к **ровно одному** человеку (`x`) и заставить его переставить палец на другого человека (`y`). Нужно найти такую одну пару `x` и `y`, чтобы после изменения вся путаница исчезла и получилась одна общая цепочка. Если одной заменой это сделать нельзя — выводим `-1 -1`.

**Входные данные:**
* В первой строке находится натуральное число **n** (2 ≤ n ≤ 10⁵) — количество школьников. 
* В следующей строке находится **n** натуральных чисел **a_i** (1 ≤ a_i ≤ n) — ученик, который достался Тайному Санте с номером **i**.

**Выходные данные:**
* В первой строке выведите два числа **x** и **y** через пробел (1 ≤ x, y ≤ n, x ≠ y) — номер ученика **x**, которому нужно изменить число **a_x**, и новое значение **y**. При этом должно выполняться условие: новое значение не должно совпадать со старым (**a_x ≠ y**). 
* Если ответов несколько — разрешается вывести любой. 
* Если сделать это невозможно (нельзя обойтись ровно одним изменением) — выведите `-1 -1`.

**Примеры:**
Пример 1
Ввод
3
1 2 3

Вывод
-1 -1

Пример 2
Ввод
3
1 3 1

Вывод
1 2

**Замечания:**
* В первом примере хотя бы один школьник будет дарить подарок сам себе. Одной заменой единый цикл не построить.
* Во втором примере после изменения происходят передачи подарков: 1 → 2 → 3 → 1.

```python
# Паттерны: Частотный массив (Frequency Map), Обход графа / Проверка цикла (Cycle Detection)
# Обоснование: Проверяем степени входа узлов и ищем один большой цикл.
# Сложность: O(N) по времени и O(N) по памяти

n = int(input())
target_idx = [int(i) - 1 for i in input().split()]

# 1. Строим частотный массив (считаем входящие подарки)
gifts_count = [0] * n
for target in target_idx:
    gifts_count[target] += 1

# 2. Ищем отклонения степеней входа
zero_gifts = []
double_gifts = []

for idx, count in enumerate(gifts_count):
    if count == 0:
        zero_gifts.append(idx)
    elif count == 2:
        double_gifts.append(idx)

# Функция проверки единого цикла за O(N)
def is_single_cycle(arr):
    visited = [False] * n
    curr = 0
    for _ in range(n):
        if visited[curr]:
            return False
        visited[curr] = True
        curr = arr[curr]
    return curr == 0 and all(visited)

# КЕЙС 1: Дисбаланс подарков (один лишний, одного не хватает)
if len(zero_gifts) == 1 and len(double_gifts) == 1:
    target_zero = zero_gifts[0]
    target_double = double_gifts[0]

    # Ищем двух дарителей, которые указывают на target_double
    givers = []
    for idx, target in enumerate(target_idx):
        if target == target_double:
            givers.append(idx)

    # Проверяем первого дарителя
    test_idx = target_idx.copy()
    test_idx[givers[0]] = target_zero
    if is_single_cycle(test_idx):
        print(givers[0] + 1, target_zero + 1)
    else:
        # Если первый не подошёл, проверяем второго дарителя
        test_idx = target_idx.copy()
        test_idx[givers[1]] = target_zero
        if is_single_cycle(test_idx):
            print(givers[1] + 1, target_zero + 1)
        else:
            print(-1, -1)

# КЕЙС 2: Все получают по 1 подарку
elif len(zero_gifts) == 0 and len(double_gifts) == 0:
    # Одной заменой изменить конфигурацию нескольких кругов невозможно, 
    # так как переключение одного ребра всегда создаёт дисбаланс (0 и 2).
    print(-1, -1)

# КЕЙС 3: Слишком много аномалий, одной заменой не исправить
else:
    print(-1, -1)
```

## Problem 8: Поиск неподвижной точки на плане

**Условие:**
Миша сидел в переговорке и решил нарисовать ее план на листке бумаги. Когда он закончил рисовать план переговорки, он положил лист с планом на пол переговорки. Теперь ему стало интересно: а есть ли на плане точка, которая лежит ровно на том месте пола, за которое она отвечает? 

Помогите ему найти эту точку.

**Входные данные:**
Переговорка и ее план имеют форму прямоугольника. 
1. Первая строка: два вещественных числа **X** и **Y** (1 ≤ X, Y ≤ 1000) — координаты.
   Координаты углов переговорки равны (0,0), (X,0), (X,Y), (0,Y).
2. Вторая строка: восемь вещественных чисел, описывающих координаты углов плана переговорки. Они идут парами в строгом соответствии с углами реальной комнаты:
  1. Координаты угла плана для угла комнаты (0, 0)
  2. Координаты угла плана для угла комнаты (X, 0)
  3. Координаты угла плана для угла комнаты (X, Y)
  4. Координаты угла плана для угла комнаты (0, Y)

*Гарантируется, что план прямоугольный, масштаб строго меньше 1 и не менее 0.0001, и лист не выходит за границы комнаты.*

**Выходные данные:**
* Два вещественных числа через пробел — координаты неподвижной точки в координатах переговорки. Выводить числа нужно с точностью не менее четырех знаков после запятой.

**Пример 1:**
Ввод
```text
10 5
3.0 2.5 1.0 2.5 1.0 1.5 3.0 1.5
```

Вывод
```text
2.5000 2.0083
```

**Замечание:**
Для читаемости условий входные данные в примере даются с меньшим количеством десятичных знаков. В реальных тестовых данных числа будут вещественными с точностью до 5 знаков после запятой.

```python
# Паттерн: Бинарный поиск по ответу в 2D (Binary Search on 2D Space) / Билинейная интерполяция
# Почему: Позволяет сужать рамки поиска точки пересечения систем координат без явного решения систем уравнений.
# Сложность: По времени O(log(1/точность)), по памяти O(1)

room_x, room_y = [float(i) for i in input().split()]

coords = [float(i) for i in input().split()]
# Разделение координат углов плана на отдельные составляющие x и y
p00_x, p00_y = coords[0], coords[1]
px0_x, px0_y = coords[2], coords[3]
pxy_x, pxy_y = coords[4], coords[5]
p0y_x, p0y_y = coords[6], coords[7]

# Функция для вычисления физических координат точки на плане
def get_plan_coords(rx, ry):
    kx = rx / room_x
    ky = ry / room_y

    # Раздельный расчёт для осей x и y с использованием координат углов плана
    x = (1 - kx) * (1 - ky) * p00_x + kx * (1 - ky) * px0_x + kx * ky * pxy_x + (1 - kx) * ky * p0y_x
    y = (1 - kx) * (1 - ky) * p00_y + kx * (1 - ky) * px0_y + kx * ky * pxy_y + (1 - kx) * ky * p0y_y

    return x, y

# Границы области поиска в реальной комнате
x_min, x_max = 0.0, room_x
y_min, y_max = 0.0, room_y

# Итерационное деление площади для достижения необходимой точности
for _ in range(100):
    mid_x = (x_min + x_max) / 2
    mid_y = (y_min + y_max) / 2

    plan_x, plan_y = get_plan_coords(mid_x, mid_y)

    if plan_x > mid_x:
        x_min = mid_x
    else:
        x_max = mid_x

    if plan_y > mid_y:
        y_min = mid_y
    else:
        y_max = mid_y

print(f"{x_min:.5f} {y_min:.5f}")

```

## Problem 9: Оптимизация купонов на обеды

**Условие:**
Даня в обеденный перерыв ходит в одно и то же кафе. Ему, как сотруднику банка, положено специальное предложение: при каждой покупке больше, чем на **100** рублей, Даня получает купон на бесплатный обед.

Даня узнал стоимость своих обедов на ближайшие **n** дней. Ему хочется минимизировать свои затраты, грамотно используя талоны. Требуется найти минимальные суммарные затраты Дани на обеды.

**Входные данные:**
* В первой строке дается натуральное число **n** (0 ≤ n ≤ 100) — количество дней.
* В каждой из следующих **n** строк записана стоимость обеда в соответствующий день (неотрицательное целое число, не больше, чем 300).

**Выходные данные:**
* В первой строке выдайте минимально возможную суммарную стоимость обедов.

**Пример 1:**
Ввод
```text
5
35
40
101
59
63
```

Вывод
```text
235
```

**Замечание:**
В первом примере Дане придется купить первые 3 обеда (35 + 40 + 101 = 176 рублей), после чего за обед стоимостью 101 рубль у него появится купон. Этот купон выгоднее всего потратить на самый дорогой из оставшихся обедов — последний (63 рубля). Четвёртый обед (59 рублей) он покупает за деньги. Итого: 35 + 40 + 101 + 59 + 0 = 235 рублей.

```python
# Паттерн: Динамическое программирование (Dynamic Programming)
# Почему: Текущий выбор (платить или тратить купон) зависит от прошлого.
# Считаем минимальную стоимость для каждого дня, зная количество купонов на руках.
# Сложность: По времени O(N^2) — для каждого из N дней мы перебираем до N возможных купонов.
#            По памяти O(N^2) — храним таблицу состояний размера N x N. Для N=100 это мгновенно.

n = int(input())
# Если дней 0, то и тратить ничего не нужно
if n == 0:
    print(0)
else:
    prices = [int(input()) for _ in range(n)]

    # Константа для обозначения бесконечности (недостижимое состояние)
    INF = float('inf')

    # Создаём таблицу DP шаблоном списочного включения
    # Строки — это дни (от 0 до n), столбцы — купоны на руках (от 0 до n)
    # Изначально все ячейки заполняем бесконечностью
    dp = [[INF] * (n + 1) for _ in range(n + 1)]

    # Стартовая точка (0-й день, 0 купонов, потрачено 0 рублей)
    dp[0][0] = 0

    # Заполняем таблицу день за днём
    for day in range(n):
        price = prices[day]
        for coupons in range(n):
            # Если текущее состояние недостижимо, пропускаем его
            if dp[day][coupons] == INF:
                continue

            # ВАРИАНТ 1: Даня покупает обед за деньги
            if price > 100:
                # Получаем +1 купон к текущим
                next_coupons = coupons + 1
                if next_coupons <= n:
                    dp[day + 1][next_coupons] = min(dp[day + 1][next_coupons], dp[day][coupons] + price)
            else:
                # Количество купонов не меняется
                dp[day + 1][coupons] = min(dp[day + 1][coupons], dp[day][coupons] + price)

            # ВАРИАНТ 2: Даня тратит купон (если он есть)
            if coupons > 0:
                # Тратим 1 купон, платим 0 рублей
                dp[day + 1][coupons - 1] = min(dp[day + 1][coupons - 1], dp[day][coupons])

    # Вывод минимально возможной стоимости из всех вариантов финального дня
    print(min(dp[n]))
```
