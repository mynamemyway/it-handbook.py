## Принципы проектирования кода (SOLID, DRY, KISS) 📜

### 1. KISS — Keep It Simple, Stupid («Делай проще, дурачок»)

- Суть: Код должен быть максимально простым, понятным и прямолинейным. Избегай избыточного усложнения, «умных» трюков и преждевременной оптимизации.
- Пример в DSA: Если задачу можно решить простым циклом, не нужно городить сложную рекурсию или паттерны проектирования ради того, чтобы код выглядел «круто». Чем проще код, тем меньше в нем багов и тем легче его поддерживать.

### 2. DRY — Don't Repeat Yourself («Не повторяйся»)

- Суть: Каждая часть логики или знаний должна иметь единственное, однозначное представление в коде. Избегай дублирования кода (copy-paste).
- Пример в DSA: Если в алгоритме тебе нужно трижды в разных местах сортировать массив и фильтровать отрицательные числа, не пиши этот код три раза. Вынеси эту логику в отдельную вспомогательную функцию (helper-метод) и вызывай её.

---

### 📜 SOLID Принципы 
SOLID — это 5 правил ООП, которые делают код гибким и удобным для тестирования.

1. **S** (Single Responsibility Principle) — Принцип единственной ответственности
   - **Суть**: Один класс или одна функция должны иметь только один повод для изменения (решать одну конкретную задачу).
   - **Пример**: Класс `Order` должен только считать стоимость заказа. Он не должен отправлять email-уведомления или сохранять данные в базу. Для этого создаются отдельные классы `EmailService` и `OrderRepository`.

2. **O** (Open/Closed Principle) — Принцип открытости/закрытости
   - **Суть**: Программные сущности должны быть открыты для расширения, но закрыты для модификации.
   - **Пример**: При добавлении нового способа оплаты (например, Криптовалюта) нельзя переписывать старый код класса `PaymentProcessor`. Нужно расширить систему: создать класс `CryptoPayment`, реализующий общий интерфейс оплаты.

3. **L** (Liskov Substitution Principle) — Принцип подстановки Барбары Лисков
   - **Суть**: Наследники должны дополнять, а не ломать логику родителя. Вы должны иметь возможность заменить родительский класс любым его дочерним классом, и программа не должна сломаться.
   - **Пример**: Класс `Пингвин` наследуется от класса `Птица`. Если в классе `Птица` есть метод `fly()`, а `Пингвин` при его вызове выбрасывает ошибку `CanNotFlyError` — принцип нарушен. Наследник сломал ожидания от родительского класса.

4. **I** (Interface Segregation Principle) — Принцип разделения интерфейса
   - **Суть**: Много специализированных интерфейсов лучше, чем один универсальный. Клиенты не должны зависеть от методов, которые они не используют.
   - **Пример**: В Python (через абстрактные классы) не нужно создавать один огромный класс-робот с методами `cook()`, `drive()` и `code()`. Разделите его на мелкие сущности, чтобы класс-повар не был обязан реализовывать ненужный ему метод `code()`.

5. **D** (Dependency Inversion Principle) — Принцип инверсии зависимостей
   - **Суть**: Высокоуровневые модули не должны зависеть от низкоуровневых. Оба должны зависеть от абстракций (интерфейсов), а не от конкретных реализаций.
   - **Пример**: Класс `Car` не должен жестко внутри себя создавать двигатель `self.engine = V8Engine()`. Он должен принимать его как аргумент при инициализации: `def __init__(self, engine)`. Тогда в машину можно будет передать и `ElectricEngine`, и `V6Engine`, не меняя код самого автомобиля.

## Тема 1: Big O Нотация 🅾️

### Измеряем Код, а не Время ⏱️

Представьте, что вам нужно отправить другу файл.

- Если файл маленький (1 КБ), отправка через интернет займет секунду.
- Если файл огромный (1 ТБ), возможно, быстрее будет сесть в машину, доехать до дома друга и передать жесткий диск лично.

**Big O Notation** — это способ расчета этой «эффективности». Мы не измеряем скорость в секундах (потому что это зависит от мощности компьютера). Мы измеряем, как растет количество **операций (шагов)** с увеличением объема входных данных.

На собеседованиях нас всегда интересует **Худший Сценарий (Worst Case)**. Мы хотим знать: «Если входных данных станет очень много (например, миллион пользователей), `упадет` ли мое приложение?»

---

### Виды временной сложности (Time Complexity)

#### 1. O(1) — Константное время (Лучшее) ⚡

Независимо от количества данных, операция занимает одно и то же время.

- **Аналогия:** Заказ пиццы. Усилия на звонок в пиццерию одинаковы, заказываете ли вы 1 пиццу или 100 пицц. Вы делаете всего **один звонок**.

```python
def get_first_item(items):
    # Неважно, в списке 10 элементов или 10 000, это все равно одна операция
    return items[0]
```

#### 2. O(log n) — Логарифмическое время (Очень быстро) 🌲

Обычно возникает, когда мы отсекаем половину задачи на каждом шаге.

- **Аналогия:** Поиск слова в бумажном словаре. Вы открываете середину, понимаете, что слово во второй половине, и игнорируете первую. Вы продолжаете делить пополам, пока не найдете слово.

#### 3. O(n) — Линейное время (Нормально) 🚶‍♂️

Если вы удвоите входные данные, время выполнения тоже удвоится.

- **Аналогия:** Раздача листовок. Если людей 10, это займет 10 минут. Если людей 100, это займет 100 минут.

```python
def find_item(items, target):
    # Худший случай: элемент находится в самом конце списка
    for item in items:
        if item == target:
            return True
    return False
```

#### 4. O(n^2) — Квадратичное время (Опасная зона) 🐌

Обычно вызывается **Вложенными Циклами** (цикл внутри цикла). Если данные удваиваются, время увеличивается в 4 раза!

- **Аналогия:** Вы на вечеринке и хотите, чтобы каждый гость пожал руку каждому другому гостю.

```python
def print_pairs(items):
    for i in items:      # Внешний цикл
        for j in items:  # Внутренний цикл
            print(i, j)
```

### Пространственная Сложность (Space Complexity) 📦

Время — не единственный ресурс; **Память (RAM)** тоже ограничена. Space Complexity измеряет, сколько **дополнительной памяти** требует ваш алгоритм.

- **O(1) Space:** Вы используете всего несколько переменных (например, `i = 0` или `sum = 0`).
- **O(n) Space:** Вы создаете новый список, который хранит столько же элементов,

---

### Шпаргалка

| Нотация      | Имя         | Скорость        | Вердикт                         |
| :----------- | :---------- | :-------------- | :------------------------------ |
| **O(1)**     | Constant    | Мгновенно       | ✅ Отлично                      |
| **O(log n)** | Logarithmic | Очень быстро    | ✅ Супер (Бинарный поиск)       |
| **O(n)**     | Linear      | Пропорционально | 👌 Нормально                    |
| **O(n^2)**   | Quadratic   | Медленно        | ⚠️ Избегайте на больших данных  |

---

### Совет для LeetCode 💡

Всегда смотрите на **Constraints (Ограничения)** внизу задачи.

• Если **n <= 10^5** (100,000), решение **O(n^2)** скорее всего получит ошибку **Time Out (TLE)**. Вам нужно **O(n)** или **O(n log n)**.
• Если **n <= 20** (очень мало), можно использовать **O(2^n)** (бэктрекинг).

## Тема 2: Память 101 🗄️

### Где живет ваш код?

Когда ваша программа запускается, компьютер выделяет ей блок оперативной памяти (RAM). Эта память делится на две очень разные секции: **Стек (Stack)** и **Куча (Heap)**.

Понимание разницы между ними помогает понять, почему одни операции выполняются быстро, а другие — медленно.

---

#### 1. Стек (Упорядоченный и Быстрый)

Представьте Стек как стопку тарелок в буфете. Вы можете положить тарелку только сверху и взять тарелку только сверху.

*   **Как это работает:** Здесь хранятся временные переменные, создаваемые функциями.
*   **Поведение:** Last-In, First-Out (LIFO — «Последним пришел — первым ушел»).
*   **Скорость:** Чрезвычайно быстро. Процессор управляет этим автоматически.
*   **Ограничение:** Он маленький. Если вы поместите в него слишком много данных (например, бесконечный рекурсивный цикл), произойдет **Переполнение стека (Stack Overflow)**.

```python
def simple_function():
    x = 10  # Хранится в Стеке
    y = 20  # Хранится в Стеке
    return x + y
    
# Когда функция завершается, x и y мгновенно удаляются из Стека
```

---

#### 2. Куча (Беспорядочная и Большая)

Представьте Кучу как огромный, беспорядочный склад. Вы можете положить вещи куда угодно, где есть свободное место, но вам нужен точный адрес («указатель» или «ссылка»), чтобы найти их снова.

*   **Как это работает:** Здесь хранятся глобальные переменные и сложные объекты (такие как списки, классы, хеш-таблицы).
*   **Поведение:** Произвольный доступ.
*   **Скорость:** Медленнее, чем Стек. Компьютеру нужно найти адрес, чтобы добраться до ваших данных.
*   **Ограничение:** Если не управлять ею правильно (в языках типа C++), возникают **Утечки памяти (Memory Leaks)**. В Python или Java за вас это делает **«Сборщик мусора» (Garbage Collector)**, что немного снижает производительность.

```python
def complex_function():
    # Переменная 'my_list' (ссылка) находится в Стеке.
    # САМИ данные списка [1, 2, 3...] хранятся в Куче.
    my_list = [1, 2, 3, 4, 5]
```

---

#### Где хранятся массивы и списки? ✏️
В современных высокоуровневых языках (Python, Java, JS) все динамические объекты, включая массивы и встроенные списки, всегда хранятся в куче.

* В стеке лежит только крошечная переменная-указатель-ссылка (адрес в памяти).
* В куче лежит сам массив (структура данных и все элементы).

#### Стек против Кучи: Сравнение

| Характеристика | Стек (The Stack)                  | Куча (The Heap)                            |
| :------------- | :-------------------------------- | :----------------------------------------- |
| Хранение       | Простые переменные (int, boolean) | Сложные объекты (массивы, списки, объекты) |
| Размер         | Фиксированный (Маленький)         | Динамический (Большой)                     |

---

#### Список в Python под капотом ✏️

**Список в Python — это динамический массив.**
1. Когда ты делаешь `.append()`, Python выделяет память с запасом (over-allocation).
  *Ты добавляешь элемент, а Python резервирует место сразу под 4 или 8 элементов. Следующие несколько `.append()` проходят мгновенно (**O(1)**)*
2. Когда этот «запас» заканчивается, Python выделяет новый, более просторный кусок памяти в куче, копирует туда все старые элементы и удаляет старый список(**O(n)**).
3. Амортизированная сложность — это среднее время операции. Поскольку долгая перезапись памяти происходит редко, а быстрые добавления — часто, в среднем (амортизировано) метод `.append()` работает за **O(1)**.

---

#### Почему в LeetCode это важно?

1.  **Рекурсия использует Стек:** Каждый раз, когда рекурсивная функция вызывает сама себя, она добавляет новый слой в Стек. Если ваша рекурсия заходит слишком глубоко (обычно ~1000 вызовов), программа падает с ошибкой.
2.  **Структуры данных используют Кучу:** Когда вы создаете массивный Array или Hash Map, он живет в Куче. Доступ к нему немного «дороже», чем к простой целочисленной переменной.

---

#### 3. Бонус: Кто убирает мусор? (Garbage Collector)

В старых языках (как C или C++) программист был обязан сам удалять данные из **Кучи**. Забыл удалить — получил утечку памяти. Удалил не то — программа упала.

В современных языках (Python, Java, JavaScript, Go) работает **Garbage Collector (GC)** — автоматический «уборщик».

#### Как это работает? (Упрощенно)

Главный метод, который использует Python, называется **Подсчет ссылок (Reference Counting)**.

1. У каждого объекта в памяти есть невидимый счетчик: «Сколько переменных ссылаются на меня?».
2. Если вы создаете список `a = [1, 2, 3]`, счетчик становится равен **1**.
3. Если вы делаете `b = a`, счетчик становится равен **2**.
4. Если вы удаляете ссылки (`a = None`, `b = None`), счетчик падает до **0**.
5. Как только счетчик равен **0**, **GC** видит, что объект никому не нужен, и мгновенно стирает его, освобождая место.

> *Бывает так, что объекты в Куче ссылаются друг на друга через свойство, тогда Reference Counting здесь бессилен. Python запускает дополнительный модуль Garbage Collector (циклический сборщик мусора). Он периодически сканирует объекты в Куче, находит такие изолированные группы, которые ссылаются только друг на друга, принудительно обнуляет их счетчики и очищает память.*

---

#### Цена удобства

За эту магию приходится платить. Сборщик мусора потребляет ресурсы процессора. Иногда он может ставить программу на микро-паузу (особенно в Java), чтобы провести генеральную уборку. В **LeetCode** это редко критично, но в высоконагруженных системах об этом важно помнить.

## Тема 3: Массивы (Статические и Динамические) 🧱

### Основы 🏗️

Если вы решите выучить только одну структуру данных, пусть это будет **Массив (Array)**. Это основа для почти всего остального (Строки, Стеки, Очереди, Хеш-таблицы и Кучи — все они опираются на массивы).

#### Что такое Массив?
Это коллекция элементов, хранящихся в **непрерывной (contiguous)** памяти. Это значит, что компьютер находит свободный блок RAM и помещает элементы вплотную друг к другу, без пробелов.

---

#### Аналогия с «Местами в Кино» 🎬

Представьте Массив как ряд зарезервированных мест в кино.

*   **Индексы:** Номера кресел (0, 1, 2, 3...).
*   **Непрерывность:** Кресло 2 всегда находится сразу после Кресла 1.

---

#### 1. Произвольный Доступ (Суперсила) - O(1) ⚡

Если у вас билет на «Место 5», вам не нужно проверять Место 1, затем Место 2, затем Место 3. Вы идете **прямо** к Месту 5.

Поскольку элементы находятся рядом, компьютер может вычислить точный адрес памяти с помощью простой математики:
`Адрес = Адрес_Начала + (Индекс * Размер_Элемента)`

```python
nums = [10, 20, 30, 40, 50]

# Доступ к индексу 2
print(nums[2]) # Вывод: 30

# Стоимость: O(1) - Мгновенно
```

**Объяснение:** Как компьютер находит массив[3] за **(O(1)**
- Представь, что массив начинается в памяти по адресу 1000. Каждый элемент (например, число) занимает 4 байта.
- Компьютер делает одно действие: 1000 + (3 * 4) = 1012. Он прыгает на адрес 1012 и забирает данные.
- Размер_Элемента нужен чтобы знать, на сколько байтов умножить индекс

**Задача:** Массив строк. Все строки разной длины. Будет ли доступ к строке по индексу занимать O(1)?
**Ответ:** обращение по индексу это O(1).
**Дополнение:** Но как, если строки разной длины, и формула выше не должна работать?
**Секрет под капотом:** В массиве Python хранятся не сами строки, а ссылки (адреса) на них. Любая ссылка (указатель) в памяти имеет одинаковый фиксированный размер (обычно 8 байт). Поэтому формула работает.

---

#### 2. Вставка и Удаление (Слабость) - O(n) 🐢

Представьте, что ряд в кино заполнен. Вы хотите сесть в середину (Индекс 2).

- Вы не можете просто сесть.
- Человек на Месте 2 должен пересеть на Место 3.
- Человек на Месте 3 должен пересеть на Место 4.
- Все должны подвинуться, чтобы освободить вам место.

Этот **«Сдвиг» (Shifting)** стоит дорого. В списке из 1 миллиона элементов вставка в начало требует перемещения 1 миллиона элементов.

---

### Статические vs. Динамические Массивы

#### Статические Массивы (Старая школа)

В языках типа C++ или Java (примитивные массивы) вы должны задать размер заранее.

-  `int arr[5];` -> Создает 5 слотов.
-  **Проблема:** Если вы захотите добавить 6-й элемент, вы не сможете. Память по соседству может быть занята другой программой.

#### Динамические Массивы (Python Lists / JS Arrays)

Это то, что вы используете в Python (`list`).

-  **Как это работает:** Кажется, что место бесконечно.
-  **Под капотом:** Когда массив заполняется, язык автоматически:
  -   Создает **новый массив двойного размера**.
  -   Копирует все старые элементы в новый.
  -   Удаляет старый.

---

#### Задача: Переместить нули в конец списка с Space Complexity O(1) - без создания нового списка.

```python
def move_zeroes(nums):
    # Указатель для позиции, куда нужно записать СЛЕДУЮЩЕЕ не-нулевое число
    write_index = 0
    
    # Идем по массиву обычным циклом
    for i in range(len(nums)):
        # Если нашли НЕ ноль
        if nums[i] != 0:
            # Записываем его на позицию write_index
            nums[write_index] = nums[i]
            # Сдвигаем указатель записи на один шаг вперед
            write_index += 1
            
    # После того как все не-нули перенесены в начало,
    # заполняем оставшуюся часть массива нулями
    for i in range(write_index, len(nums)):
        nums[i] = 0
```

>*Этот код работает за O(n) по операциям и тратит O(1) дополнительной памяти, потому что мы перезаписываем старые ячейки и не создаем новые списки в Куче.*

## Тема 4: Строки (Strings) 🧵

### Что такое Строка?

Технически, Строка — это просто **Массив символов**.

`"Hello"` — это на самом деле `['H', 'e', 'l', 'l', 'o']`.

Поскольку под капотом это массивы, они обладают той же суперсилой: **Мгновенный доступ (O(1))**. Вы можете получить 3-й символ мгновенно, обратившись к `s[2]`.

---

### Главный подвох: Неизменяемость (Immutability) 🔒

Во многих популярных языках (Python, Java, JavaScript, C#) строки являются **Неизменяемыми (Immutable)**. Это означает, что их нельзя изменить после создания.

Представьте строку как **Каменную Скрижаль**. Вы не можете стереть букву и написать новую. Вы должны высечь совершенно новую плиту.

Если вы попытаетесь изменить символ, компьютер не меняет исходную строку. Он создает совершенно новую копию строки в памяти с учетом изменений.

```python
s = "Hello"

# s[0] = "J"  <-- ❌ ОШИБКА! Камень нельзя изменить.

# Вместо этого вы должны создать НОВУЮ строку:
# Это копирует 'ello', добавляет 'J' и сохраняет в новой
s = "J" + s[1:]
```

---

### Ловушка Конкатенации ⚠️

При `s += " World!"` Python не дописывает буквы в конец старой строки. Он создает в другом месте памяти новую строку «Hello World!» и перенаправляет на нее переменную `s`.

То есть, `+=` для строк каждый раз принудительно копирует все буквы в новый объект в Куче за **(O(n))**.
Из-за неизменяемости сложение строк внутри цикла опасно для производительности.

**Плохой код O(n²):**

Каждый раз, когда вы делаете `+=`, компьютер создает новую копию.

* "Н"
* "Не" (Копирует "Н", добавляет "е")
* "Hel" (Копирует "Не", добавляет "l")
* ...и так далее.

```python
result = ""

for char in large_list:
    # ❌ НЕВЕРНО! Создает новую копию для КАЖДОГО символа
    result += char
```

**Хороший код O(n):**

Используйте **Список (List)**. Списки изменяемы (как маркерная доска, а не камень). Вы собираете все символы и объединяете их один раз в конце.

```python
chars = []

for char in large_list:
    chars.append(char)  # БЫСТРО: Добавление в список

# БЫСТРО: Создает строку только один раз
result = "".join(chars)
```

---

### Операции со строками

#### 1. Подстрока / Срез (Slicing) 🍰
Получение части строки (например, `s[2:5]`).

* **Сложность:** `O(k)`, где k — длина среза.
* **Почему:** Компьютер должен скопировать (создать) новый объект для каждого символа в памяти.

#### 2. Поиск (оператор `in`) 🔍
Проверка, есть ли "cat" внутри "vacation".

* **Сложность:** `O(n × m)` (Наивный) или `O(n)` (Оптимизированный).
* **Почему:** В худшем случае нужно проверить каждую начальную позицию в тексте.

---

### Совет для LeetCode 💡
Многие задачи на строки — это на самом деле замаскированные задачи на Массивы.

1. **Анаграммы (Anagrams):** «Являются ли 'listen' и 'silent' анаграммами?»
  - **Трюк:** Подсчитайте частоту символов, используя Хеш-карту или Массив размером 26 (для a-z).
2. **Палиндромы (Palindromes):** «Читается ли 'racecar' одинаково задом наперед?»
  - **Трюк:** Используйте Два указателя (Тема 9). Один указатель в начале, другой в конце. Сравнивайте и двигайтесь внутрь.

## Тема 5: Связные Списки (Linked Lists) 🔗

### Что такое Связный Список?

Если **Массив** — это шеренга солдат, стоящих плечом к плечу, то **Связный Список** — это группа шпионов, разбросанных по городу, где каждый шпион знает местоположение только следующего шпиона. У LL нет индексов -> единого базового адреса и фиксированного шага

В отличие от Массивов, где данные плотно упакованы в непрерывной памяти (Куче/Heap), узлы Связного Списка **разбросаны** случайным образом по всей памяти компьютера (Куче/Heap).

---

#### В теории LeetCode есть два разных понятия ✏️

1. Физическое место хранения (Стек/Куча)
2. Способ организации данных внутри этого места (Непрерывный/Разбросанный)
   - Массив (и список Python) в куче — это «монолит»:
   Для массива выделяется один непрерывный, сплошной кусок кучи. Все элементы сидят строго друг за другом вплотную. Компьютер знает, где начало, и может мгновенно прыгнуть к любому элементу по индексу.
   - Связный список в куче — это «Фрагментированная (разбросанная) цепочка»:
   Каждый узел (ListNode) создается отдельно в случайных, свободных местах кучи. Между узлом A и узлом B в памяти могут лежать совершенно другие данные приложения. Они связаны только цифровым адресом — указателем next.

**Резюме**
- Массив = непрерывный блок памяти (внутри кучи).
- Связный список = разрозненные осколки памяти (внутри кучи).

---

#### "Узел" (Node): Атомарная Единица
В контексте DSA слово **«атомарная»** (от греческого atomos — неделимый) означает самую мелкую, базовую единицу, из которой строится всё остальное.

**На примере УЗЛА (Node):**

1. **Неделимость:** Узел — это минимальный «кирпичик». Вы не можете разделить узел на части и при этом сохранить логику списка. Если вы уберете из узла данные или ссылку, он перестанет быть узлом.
2. **Самодостаточность:** Один узел содержит в себе всё необходимое, чтобы быть частью структуры: само значение и адрес, где искать соседа.
3. **Единообразие:** Весь список — это просто цепочка из множества таких одинаковых «атомов».

---

Чтобы хранить эти разбросанные данные связанными, каждый элемент должен содержать две вещи. Мы называем этот контейнер **Узлом (Node)**:

1.  **Value (val, Значение):** Фактические данные, которые вы хотите сохранить (например, число 42).
2.  **Next Pointer (next, Указатель):** Адрес (светящаяся стрелка), который точно говорит, где в памяти прячется следующий узел.

---

#### Аналогия с Охотой за Сокровищами 🏴‍☠️

Думайте о **Массиве** как об **учебнике**. Если я скажу вам прочитать страницу 50, вы точно знаете, где она, и мгновенно открываете ее (**O(1)**).

Думайте о **Связном Списке** как об **Игре-квесте (Scavenger Hunt)**.

-  У вас есть только первая подсказка (**Head / Голова**).
-  Вы должны пойти в первое место, чтобы найти записку, которая приведет вас во второе место.
-  **Критическое ограничение:** Вы не можете перепрыгнуть сразу к 5-й подсказке. Вы обязаны физически посетить локации 1, 2, 3 и 4, чтобы найти ее. Вот почему чтение происходит медленно **O(n)**.

---

#### Структура Кода

- В реальной разработке на Python для работы со связными списками используется встроенный класс `collections.deque` (или встроенные классы для массивов, как в Python `[]` или Java `ArrayList`)
- В LeetCode вы должны построить цепочку узлов вручную через `ListNode`. Вы увидите это определение почти в каждой задаче:

```python
# Это чертеж одного "шпиона" или "подсказки"
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val    # Данные (Секретное сообщение)
        self.next = next  # Указатель (Карта к следующему шпиону)

# Создание небольшого списка: 1 -> 2 -> 3
node1 = ListNode(1)
node2 = ListNode(2)
node3 = ListNode(3)

# Связываем их вручную
node1.next = node2 # node1 теперь указывает на node2
node2.next = node3 # node2 теперь указывает на node3

# node3.next по умолчанию None, отмечая конец.
head = node1 # Начало нашего списка
```

---

### База «процедурного» подхода к спискам, где мы работаем напрямую с узлами.

#### 1. Обход списка (Печать)

«Поставить палец на Голову». Мы используем цикл `while`, потому что не знаем заранее, сколько в списке узлов.

```python
def print_list(head):
    curr = head  # Ставим "указатель" на начало

    while curr is not None:  # Пока не упремся в пустоту (конец списка)
        print(curr.val)      # Печатаем данные текущего узла
        curr = curr.next     # ПЕРЕХОД: перемещаем указатель на следующий адрес в Куче

    print("Конец списка!")
```

#### 2. Вставка в Начало (Prepend) - Суперсила ⚡️ (Правильный порядок)

Критически важна последовательность. Если сначала изменить `head`, мы потеряем адрес всей остальной цепочки.

```python
def insert_at_front(head, new_val):
    new_node = ListNode(new_val)  # 1. Создали новый объект

    # 2. Сначала привязываем НОВЫЙ узел к СТАРОМУ началу.
    #    Теперь новый узел "держит" всю остальную цепь.
    new_node.next = head

    # 3. И только теперь объявляем новый узел официальным началом (head).
    head = new_node
    return head
```

#### 3. Разбор "Плохого кода" ⚠️ (Почему это ловушка)

Если порядок нарушен:

```python
new_node = ListNode(99)
head = new_node        # ОШИБКА: Мы забыли, где был старый список.
new_node.next = head   # ОШИБКА: Узел зациклился на себе.
```

**Результат:** Все старые данные (1 → 2 → 3) остались в Куче, но ссылок на них больше нет. Сборщик мусора Python их удалит. Ты «отрезал» голову от туловища.

---

#### 4. Удаление Узла

Чтобы удалить узел (скажем, узел **B** в `A -> B -> C`), вы не уничтожаете **B** физически. Вы просто следите за тем, чтобы на него больше ничего не указывало.

Вы меняете стрелку **A** так, чтобы она указывала прямо на **C**, перепрыгивая через **B**. Узел **B** теперь отключен, и сборщик мусора (garbage collector) в конечном итоге съест его.

---

### Важные техники для собеседований

Вы почти никогда не используете «сырой» Связный Список в реальном коде. Но на собеседованиях они используются для проверки вашей способности управлять сложной логикой указателей, не запутываясь.

#### 5. Секретное оружие: Dummy Node (Фиктивный узел) 🧠

Это концепция, которой часто не хватает для уверенности. Зачем нам узел со значением -1, которое «не важно»?

**Проблема:** Когда ты удаляешь или вставляешь узел, тебе всегда нужно знать «предыдущий» (`prev`). Но у самого первого узла (головы) нет предыдущего. Это заставляет писать кучу `if head is None`.

**Решение:** Мы создаем «подставного» шпиона перед настоящим списком.

```python
# Dummy Node — это предохранитель
dummy = ListNode(-1)   # Создаем пустой узел-заглушку
dummy.next = head      # Привязываем его ПЕРЕД настоящим началом

# ТЕПЕРЬ:
# У самого первого реального узла (head) ТОЖЕ есть предыдущий — это dummy.
# Нам больше не нужны проверки "а не пуст ли список?",
# потому что dummy всегда существует.

# В конце работы мы просто возвращаем:
return dummy.next  # Это и есть наше реальное начало списка
```

#### 6. Быстрый и Медленный Указатели (Черепаха и Заяц) 🐢🐇

Это паттерн, используемый в **30%** задач на связные списки. У вас есть два указателя, движущихся с разной скоростью.

-  **Медленный указатель (slow):** Движется на **1 шаг** за раз (`slow = slow.next`).
-  **Быстрый указатель (fast):** Движется на **2 шага** за раз (`fast = fast.next.next`).

#### Сценарии использования:

1. **Поиск Середины:** Когда `fast` (Заяц) достигает финиша, `slow` (Черепаха) будет ровно на полпути.
2. **Обнаружение Цикла:** Если список зацикливается на себе, быстрый бегун в конечном итоге обгонит медленного бегуна на круг и догонит его сзади. Если они когда-нибудь встретятся, значит, есть цикл.

---

**Итог:**

1. **Индексов нет.** Мы работаем только с объектами и ссылками `.next`.
2. **Безопасность:** Сначала связывай новый узел с хвостом, а потом перенаправляй голову.
3. **Dummy Node:** Используй его, чтобы код стал чище и не раздувался от проверок `if`.

> *Dummy Node никогда не несет полезных данных, его роль — просто "подержать дверь", чтобы алгоритм не сломался на пустом списке.*

### Сложность связных списков (Итоговая таблица)

| Операция                        | Сложность | Описание                                         |
| :------------------------------ | :-------- | :----------------------------------------------- |
| **Доступ / Чтение** `node[i]`   | **O(n)**  | Медленно. Нужно идти по цепочке шаг за шагом.    |
| **Вставка в Head**              | **O(1)**  | Супер быстро. Просто обновите 2 указателя.       |
| **Удаление в Head**             | **O(1)**  | Супер быстро. Просто сдвиньте указатель head.    |
| **Вставка/Удаление в середине** | **O(n)**  | Вам нужно пройти O(n), чтобы сначала найти место.|

*Примечание: Связные списки хорошо подходят для задач, когда мы часто удаляем/добавляем элементы в начало/конец и не так часто в середину.*

## Тема 6: Продвинутые Связные Списки (Doubly & Circular) 🔄

### 1. Двусвязные Списки (Doubly Linked Lists - DLL)

В предыдущей теме мы изучили **Односвязный Список**. Это была улица с односторонним движением. Если вы пропустили поворот или вам нужно было посмотреть на предыдущий элемент, вам не везло; приходилось начинать всё с самого начала.

**Двусвязный Список (DLL)** — это улица с двусторонним движением.
Он решает проблему «навигации назад», добавляя второй указатель к каждому узлу.

#### Структура
Каждый узел теперь хранит **три** элемента информации вместо двух:

1. **Value (val):** Данные.
2. **Next Pointer (next):** Указывает на следующий узел (Вперед).
3. **Prev Pointer (prev):** Указывает на предыдущий узел (Назад).

```python
class DListNode:
    def __init__(self, val=0, next=None, prev=None):
        self.val = val
        self.next = next  # Стрелка вперед
        self.prev = prev  # Стрелка назад
```

---

#### Аналогия с «Историей Браузера» 🌍

Представьте Двусвязный Список как **Историю вашего Веб-браузера**.

- **Текущая страница:** Узел, на который вы сейчас смотрите.
- **Кнопка «Вперед»:** Ведет на страницу, которую вы посетили *после* этой (**Forward Pointer**).
- **Кнопка «Назад»:** Ведет на страницу, которую вы посетили *до* этой (**Prev Pointer**).

Без этого указателя «Prev» кнопка «Назад» требовала бы перезагрузки всей вашей истории с самого начала каждый раз!

---

#### Глубокое погружение: Операции в DLL

##### Суперсила: Удаление за O(1) (С нюансом)

В **Односвязном Списке**, если я дам вам указатель на Узел **B** и скажу «Удали это», вы на самом деле **не можете** сделать это эффективно.
  - **Почему?** Чтобы удалить **B**, вам нужно изменить стрелку **A**, чтобы она указывала на **C**. Но **B** не знает, где находится **A**! Вам придется искать с Головы (**O(n)**).

В **Двусвязном Списке**, Узел **B** точно знает, кто стоит позади него (**B.prev**).
  - Вы можете дотянуться назад до **A** и вперед до **C**, и соединить их напрямую, минуя **B**.
  - **Результат:** Удаление происходит за **O(1)**.

```python
def delete_node(node):
    # node - это тот узел, который мы хотим удалить (например, B)
    prev_node = node.prev  # A
    next_node = node.next  # C

    if prev_node:
        prev_node.next = next_node  # A указывает на C
    if next_node:
        next_node.prev = prev_node  # C указывает обратно на A

    # B теперь отключен и будет удален сборщиком мусора.
```

---

#### Цена: Сложность Подключения 🧶

Платой за эту силу является сложность. При вставке узла вы должны управлять **четырьмя** указателями вместо двух. Если вы забудете хотя бы один, ваш список сломается.

#### Чтобы вставить `New` между `A` и `B`:

1.  `New.next` -> **B**
2.  `New.prev` -> **A**
3.  `A.next` -> **New**
4.  `B.prev` -> **New**

### 2. Кольцевые Списки (Circular Linked Lists) 🎡

**Кольцевой Связный Список** — это список, который никогда не заканчивается. Указатель `next` самого последнего узла не указывает на `None` — он указывает обратно на **Head (Голову)**.

#### Сценарии Использования

- **Многопользовательские Игры:** Игрок 1 -> Игрок 2 -> Игрок 3 -> (Обратно к) Игрок 1.
- **Планирование CPU:** Ваш компьютер дает 5мс Chrome, затем 5мс Spotify, затем 5мс VS Code, затем возвращается к Chrome.

---

#### Опасность ⚠️

Вы не можете использовать простой цикл `while curr`, потому что `curr` никогда не будет `None`. Ваша программа зависнет в **Бесконечном Цикле**.

### 3. Deque в Python (Double-Ended Queue - двусторонняя очередь) ✏️

#### Почему deque — это и есть двусвязный список?
В исходном коде Python (на языке C) структура deque устроена как цепочка блоков памяти, связанных друг с другом указателями «вперед» и «назад».

Хотя слово deque расшифровывается как Double-Ended Queue (двусторонняя очередь) и описывает скорее поведение (можно добавлять и удалять элементы с обоих концов), его физическая структура — это классический двусвязный список.

#### Как deque заменяет двусвязный список на практике?
Она обладает всеми ключевыми свойствами двусвязного списка:

- Вставка и удаление в начале и конце происходят за мгновенное время **O(1)**. У обычного массива [] вставка в начало занимает **O(N)**, так как нужно сдвинуть все элементы.
- Память выделяется динамически отдельными блоками, а не одним сплошным монолитом.

В модуле **collections** есть встроенная структура **deque** (двусторонняя очередь). Под капотом она реализована именно как двусвязный список (где каждый узел знает и следующий, и предыдущий элемент).

```python
from collections import deque

# Создает двусвязный список
linked_list = deque([10, 20, 30]) 

# Быстрая вставка в начало (O(1)), чего нет у обычных массивов
linked_list.appendleft(5) 
```

#### Можно использовать большинство списочных методов ✏️
*Класс deque полностью берет на себя всю рутину по управлению указателями*

- Что работает так же: вы можете перебирать его в цикле for x in `linked_list`, использовать `.append()`, `.pop()`, `.clear()`, `len()` и проверку `if 20 in linked_list`.
- Что работает иначе: доступ по индексу. Код `linked_list[2]` сработает, но он медленный! В обычном списке это происходит мгновенно, а в deque Python начнет физически шагать по связям от начала списка до 2-го элемента.
- Чего нет: у deque нет метода `.sort()`. Также нельзя делать срезы (например, `linked_list[1:3]`).
- Уникальные быстрые методы: `.appendleft()`, `.popleft()` и `.rotate()`.

```python
from collections import deque

d = deque([2, 3])
d.appendleft(1)  # вставка в начало - d теперь: deque([1, 2, 3])

---

d = deque([10, 20, 30])
first = d.popleft()  # удаление из начала - вернет 10, сама d станет: deque([20, 30])

---

d = deque([1, 2, 3, 4, 5])

# Сдвиг на 1 вправо (последний элемент 5 становится первым)
d.rotate(1)  # d теперь: deque([5, 1, 2, 3, 4])

# Сдвиг на -2 влево
d.rotate(-2) # d теперь: deque([2, 3, 4, 5, 1])
```

### Стратегия LeetCode: "LRU Cache" 🧠

Самая известная задача на собеседованиях с использованием Двусвязных Списков — это **LRU Cache (Least Recently Used)**.

**Проблема:** Разработайте структуру данных, которая хранит пары Ключ-Значение. У нее есть максимальный размер. Если она переполняется, удалите элемент, который использовался **давнее всего**.

**Решение:** Нам нужен быстрый поиск (**O(1)**) И быстрое переупорядочивание (**O(1)**).
- **Hash Map:** Хранит `Key -> Node`. (Для мгновенного доступа).
- **Doubly Linked List:** Хранит порядок. Head = Старый, Tail = Новый.

#### Алгоритм:

1. **Get(Key):** Найти узел в Карте. Отсоединить его от списка. Переместить его в **Конец** (Front/Tail).
2. **Put(Key, Val):**
  - Если ключ существует: Обновить значение, переместить в Конец.
  - Если ключ новый: Создать узел, добавить в Конец.
  - **Если Полон:** Удалить узел в Голове (Самый старый), удалить из Карты.

### Связные Списки (Singly, Doubly, Circular) ✏️
Для добавления или удаления нужно только менять ссылки.

- **Singly Linked List** — односвязный список (каждый узел ссылается только на следующий).
- **Doubly Linked List** — двусвязный список (у каждого узла есть ссылка и на следующий, и на предыдущий).
- **Circular Linked List** — кольцевой.

*Связные списки хорошо подходят для задач, когда мы часто удаляем/добавляем элементы в начало/конец и не так часто в середину.*

#### Как это работает в динамике

##### Пример 1: Обход списка (Печать)

1. Переменная curr (наш «палец») указывает на node1. curr не равен None.
2. Функция заходит в while, берет curr.val (это 10) и печатает его.
3. Строка curr = curr.next меняет значение переменной curr. Теперь внутри curr лежит ссылка на node2. Логика повторилась.
4. На третьем шаге curr становится равен node3, печатает 30.
5. Строка curr = curr.next берет значение node3.next. А у третьего узла там по умолчанию записан None.
6. curr становится равен None. Цикл while curr is not None видит, что условие нарушено, и завершает работу.

```python
# 1. Сначала создаем чертеж узла
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val      # Создаем поле для данных
        self.next = next    # Создаем поле для ссылки на следующий узел

# 2. Пишем функцию, которая умеет "шагать" по узлам
def print_list(head):
    curr = head # Ставим палец на первый узел
    
    while curr is not None: # Пока палец не соскользнул в пустоту (None)
        print(curr.val)     # Печатаем число из текущего узла
        curr = curr.next    # Передвигаем палец на следующий узел
        
    print("Конец списка!")

# ==========================================
# ЗАПУСКАЕМ ВСЁ ВМЕСТЕ:
# ==========================================

# 3. Физически создаем 3 узла в памяти компьютера
node1 = ListNode(10)
node2 = ListNode(20)
node3 = ListNode(30)

# 4. Вручную соединяем их в цепочку: 10 -> 20 -> 30 -> None
node1.next = node2
node2.next = node3
# Не передали указатель для node3, поэтому он по умолчанию None

# 5. Назначаем переменную head на самый первый узел
head = node1

# 6. Вызываем функцию и передаем ей НАЧАЛО цепочки
print_list(head)
```

##### Пример 2: полный цикл

```python
# Класс для создания отдельного элемента (узла) списка
class Node:
    def __init__(self, value):
        self.value = value  # Само данное (число, строка и т.д.)
        self.next = None    # Ссылка на следующий узел
        self.prev = None    # Ссылка на предыдущий узел (делает список двусвязным)

# Класс для управления всем списком
class DoublyLinkedList:
    def __init__(self):
        # В начале список пуст, поэтому головы и хвоста нет
        self.head = None
        self.tail = None

    # Метод добавления элемента в конец (хвост) списка
    def append(self, value):
        # 1. Создаем новый объект узла из переданного значения
        new_node = Node(value)

        # 2. Проверяем, пуст ли список (нет ли в нем "головы")
        if not self.head:
            # Если пустой, то новый узел становится одновременно и головой, и хвостом
            self.head = new_node
            self.tail = new_node
        else:
            # 3. Если в списке уже есть элементы:
            #    У текущего хвоста ставим ссылку "вперед" на наш новый узел
            self.tail.next = new_node

            # У нового узла ставим ссылку "назад" на текущий хвост
            new_node.prev = self.tail

            # 4. Переносим метку "хвост" на наш новый узел (теперь он последний)
            self.tail = new_node

# Пример работы:
list_example = DoublyLinkedList()
list_example.append("Первый")
list_example.append("Второй")

print(f"Первый элемент: {list_example.head.value}")
print(f"Второй элемент: {list_example.head.next.value}")
```

### В чем отличие deque от классических Стека и Очереди?
Стек и Очередь — это ограниченные структуры данных (абстрактные типы), а Дэк — универсальная.

- **Stack**: принцип **LIFO** — Last Input First Out. Доступ есть только к одному концу.
- **Queue**: принцип **FIFO** — First Input First Out. Вход с одной стороны, выход — с другой.
- **Deque**: это «супер-очередь». Она объединяет в себе и стек, и очередь. Вы можете использовать её как стек (через `.append()` и `.pop()`) или как очередь (через `.append()` и `.popleft()`).

В самодельном списке на **ListNode** вы можете за **O(1)** разорвать связь посередине списка и вставить туда новый узел, если ваш «палец» (указатель) уже стоит в нужном месте.
В **deque** встроенные методы не позволяют вам напрямую управлять стрелками указателей в середине. Метод `insert(index, value)` там есть, но чтобы дойти до нужного индекса, Python всё равно будет перебирать элементы, что займет время **O(N)**.

### Два симметричных варианта работы в Python для **deque** FIFO (First-In-First-Out):
1. Добавляем в конец, забираем из начала:
  - Вставка: `.append()`
  - Удаление: `.popleft()`
2. Добавляем в начало, забираем из конца:
  - Вставка: `.appendleft()`
  - Удаление: `.pop()`

### Сравнение сложности операций (Big O)

| Операция                                    | Встроенный список (list / []) | Дек (collections.deque) | Ручной список (ListNode)          |
| :------------------------------------------ | :---------------------------- | :---------------------- | :-------------------------------- |
| Доступ по индексу (в середине)              | O(1) (Мгновенно)              | O(N) (Медленно)         | O(N) (Медленно)                   |
| Вставка / Удаление в конец                  | O(1) (Быстро)                 | O(1) (Быстро)           | O(1) (Если есть ссылка на хвост)  |
| Вставка / Удаление в начало                 | O(N) (Сдвигает весь массив)   | O(1) (Мгновенно)        | O(1) (Мгновенно)                  |
| Вставка в середину (если указатель уже там) | O(N) (Сдвигает элементы)      | O(N) (Перебирает связи) | O(1) (Просто меняет стрелки)      |
| Поиск элемента по значению                  | O(N)                          | O(N)                    | O(N)                              |

### Главные выводы для собеседований

* list [] — когда нужно постоянно читать данные из случайных мест по индексам (например, arr[5]).
* deque — в задачах на очереди, когда данные постоянно заходят с одного конца и выходят с другого.
* ListNode (Ручной список) — выигрывает у всех, если нужно часто кромсать, перестраивать и склеивать списки в случайных местах без сдвига остальных элементов в памяти.

## Тема 7: Стеки (Stacks - LIFO) 🥞

Стек — это линейная структура данных, которая следует принципу **LIFO: Last-In, First-Out** (Последним пришел — первым ушел).

Это означает, что элемент, который попадает в стек последним, покидает его самым первым. Это полная противоположность Очереди (Queue).

### Аналогия: Стопка Тарелок 🍽️

Представьте пружинный диспенсер для тарелок в столовой.

1. **Push (Толкнуть):** Вы кладете новую чистую тарелку Сверху.
2. **Pop (Вытолкнуть):** Когда клиенту нужна тарелка, он берет её Сверху.
3. **Ограничение:** Вы не можете взять нижнюю тарелку. Если попытаетесь, вся стопка упадет. Вы должны сначала убрать верхние.

---

### Основные Операции

Стеки — это "ограниченные" структуры данных. По правилам стека вам запрещено заглядывать внутрь (например, обращаться к индексу `[2]` напрямую, как в Массиве). У вас есть доступ только к **Верхушке (Top)** (конец).

| Операция     | Описание                                  | Сложность            |
| :----------- | :---------------------------------------- | :------------------- |
| **Push**     | Добавить элемент наверх (в конец).        | **O(1)**             |
| **Pop**      | Удалить верхний элемент (из конца).       | **O(1)**             |
| **Peek/Top** | Посмотреть верхний элемент без удаления.  | **O(1)**             |
| **Search**   | Найти элемент в глубине.                  | **O(n)** (Медленно!) |

---

### Почему они такие быстрые?

Потому что вы никогда не сдвигаете элементы (как при вставке в Массив). Вы просто кладете элемент сверху или снимаете его.

---

### Как использовать Стек в Python 🐍

В Python нет отдельного встроенного типа данных stack. Поэтому программисты используют встроенный список `list`, но добровольно ограничивают себя:
- .append() = push
- .pop() = pop

```python
stack = []

# 1. PUSH (Добавить наверх)
# В Python "конец" списка — это "верхушка" стека.
stack.append(10)
stack.append(20)
stack.append(30)

# Стек выглядит так: [10, 20, 30] (30 наверху)

# 2. PEEK (Посмотреть наверх)
# Мы обращаемся к последнему элементу используя индекс -1
print(stack[-1])  # Вывод: 30

# 3. POP (Удалить сверху)
top_item = stack.pop()
# Возвращает 30. Стек теперь [10, 20]

# 4. Проверка на пустоту
if not stack:
    print("Стек пуст!")
```

- Текущее состояние: "Привет".

#### 2. История Браузера 🌍

- Вы заходите в Google → Push "Google".
- Вы заходите в YouTube → Push "YouTube".
- Вы жмете "Назад" → Pop "YouTube" (Возврат в Google).

#### 3. Стек Вызовов Функций (Recursion) 📞

Именно так компьютер выполняет код. Когда Функция А вызывает Функцию Б, компьютер "ставит на паузу" А и кладет её в стек. Он выполняет Б. Когда Б завершается, он достает (**pop**) А обратно, чтобы продолжить работу.

> **Заметка:** Именно поэтому бесконечная рекурсия вызывает ошибку "Stack Overflow" (Переполнение стека)!

---

### Паттерн LeetCode: «Monotonic Stack» (Монотонный Стек) 📉

Это продвинутый паттерн, используемый в задачах уровня "Medium" и "Hard" (например, *Daily Temperatures*).

**Концепция:**

Вы поддерживаете стек отсортированным (по возрастанию или убыванию), удаляя элементы, которые нарушают порядок. Это позволяет мгновенно находить нужные элементы (например, следующий больший или меньший).

Он нужен, чтобы в массиве мгновенно (за один проход) находить для каждого числа его «ближайшего большего соседа» или «ближайшего меньшего соседа». Если новый элемент нарушает порядок (например, он больше, чем элемент на верхушке стека), мы начинаем делать `pop()`, пока порядок не восстановится.

**Пример: Найти следующий больший элемент**

Вход: `[2, 1, 5]`

1. Стэк: `[2]`
2. Следующий 1. 1 > 2? Нет. Push 1. Стэк: `[2, 1]`.
3. Следующий 5. 5 > 1? Да! Pop 1 (5 — следующий больший для 1).
4. 5 > 2? Да! Pop 2 (5 — следующий больший для 2).
5. Push 5.

| **Сопоставление**      | Валидные скобки `([ ])`               |

## Тема 8: Очереди (Queues - FIFO) 🚶‍♂️🚶‍♀️

Очередь (Queue) — это линейная структура данных, которая следует принципу **FIFO: First-In, First-Out** (Первым пришел — первым ушел).

Это полная противоположность Стеку. В Стеке (**LIFO**) первым обслуживается тот, кто пришел последним. В Очереди первым обслуживается тот, кто пришел первым. Это делает Очереди «справедливыми».

### Аналогия: Очередь в Кофейне ☕

Представьте, что вы в Starbucks.

1. **Enqueue (Встать в очередь):** Вы приходите и встаете в Конец (Back) очереди.
2. **Wait (Ожидание):** Вы ждете, пока обслужат всех перед вами.
3. **Dequeue (Обслуживание):** Бариста вызывает человека из Начала (Front).
4. **Справедливость:** Если вы попытаетесь влезть в середину, люди разозлятся. Если бариста проигнорирует первого человека и обслужит последнего (поведение Стека), начнется бунт.

---

### Основные Операции

Как и Стеки, Очереди ограничены. Вы обычно не можете обращаться к элементам в середине случайным образом. Вас волнуют только **Начало (Front)** и **Конец (Back)**.

| Операция    | Описание                         | Сложность   |
| :---------- | :------------------------------- | :---------- |
| **Enqueue** | Добавить элемент в **Конец**.    | **O(1)**    |
| **Dequeue** | Удалить элемент из **Начала**.   | **O(1)**    |
| **Peek**    | Посмотреть элемент в **Начале**. | **O(1)**    |

---

### "Ловушка Python" ⚠️🚨

Это ошибка №1, которую совершают новички на собеседованиях по Python. У вас может возникнуть соблазн использовать простой `list` (список) в качестве очереди.

**НЕ ДЕЛАЙТЕ ЭТОГО.**

```python
# ❌ ПЛОХОЙ КОД (Не используйте на интервью)

queue = []

queue.append(10)   # Enqueue: O(1) - Быстро
queue.append(20)

# Проблема: Удаление с индекса 0
val = queue.pop(0)  # Dequeue: O(n) - ОЧЕНЬ МЕДЛЕННО
```

---

### Почему `pop(0)` медленный? 🐢

Помните Тему 3 (Массивы)? Массивы хранятся в непрерывной памяти.

Если вы удалите первый элемент (Индекс 0), компьютер создаст "дыру" в начале. Он не может оставить дыру.

- Он должен сдвинуть Индекс 1 на Индекс 0.
- Он должен сдвинуть Индекс 2 на Индекс 1.
- Он должен сдвинуть Индекс 3 на Индекс 2...
- Если в вашей очереди 10,000 элементов, компьютеру придется выполнить 9,999 операций сдвига только для того, чтобы удалить одного человека!

---

### Решение: `collections.deque` 🚀

Python предоставляет специализированный инструмент под названием `deque` (читается как «дек»), что означает **Double-Ended Queue** (Двусторонняя очередь).

Она реализована как Двусвязный Список небольших блоков памяти. Удаление с начала — это просто «удаление головного узла», что происходит мгновенно **O(1)**.

```python
from collections import deque

# Инициализация
queue = deque()

# 1. Enqueue (Добавить справа)
queue.append(10)
queue.append(20)
queue.append(30)

# Очередь: [10, 20, 30]

# 2. Dequeue (Удалить слева)
# Обратите внимание на имя функции: popleft
front = queue.popleft()
# Возвращает 10. Очередь: [20, 30]. Стоимость: O(1)

# 3. Peek
print(queue[0])  # Возвращает 20
```

### Когда использовать Очередь?

Если вы слышите:
- «Кратчайший путь»
- «Порядок прибытия»
- «Уровень за уровнем»

#### 1. BFS (Breadth-First Search) - Поиск в ширину 🌊

Это самый важный алгоритм в теории графов. Представьте, что вы бросили камень в пруд. Рябь расходится слоем за слоем.

- Слой 0: Камень (Старт).
- Слой 1: Вся вода в 1 дюйме от камня.
- Слой 2: Вся вода в 2 дюймах от камня.

*Чтобы запрограммировать это исследование "Слой за слоем", вы должны использовать Очередь. Вы обрабатываете всех соседей (Слой 1), потом всех соседей соседей (Слой 2)...*

#### 2. Очередь печати 🖨️

Если 5 человек отправляют документы на офисный принтер:
- Принтер помещает их в Очередь.
- Он печатает первый полученный файл первым.
- Неважно, отправил ли CEO файл последним; если стажер отправил файл на 1 минуту раньше, стажер ждет меньше.

## Тема 9: Два Указатели (Two Pointers) 👈👉

### Концепция

Паттерн **Two Pointers** — это стратегия оптимизации скорости кода. Она превращает медленное решение «в лоб» (**O(n²)**) в быстрое линейное решение (**O(n)**).

### Быстрый и Медленный Указатели (Черепаха и Заяц) 🐢🐇

Это паттерн, используемый в 30% задач на связные списки. У вас есть два указателя, движущихся с разной скоростью.

- **Медленный указатель (slow):** Движется на 1 шаг за раз (`slow = slow.next`).
- **Быстрый указатель (fast):** Движется на 2 шага за раз (`fast = fast.next.next`).

**Сценарии использования:**

1. **Поиск Середины:** Когда `fast` (Заяц) достигает финиша, `slow` (Черепаха) будет ровно на полпути.
2. **Обнаружение Цикла:** Если список зацикливается на себе, быстрый бегун в конечном итоге обгонит медленного бегуна на круг и догонит его сзади. Если они когда-нибудь встретятся, значит, есть цикл.


---

### Проблема решения «В лоб» (Brute Force)

Представьте, что вы ищете пару носков в куче.

- **В лоб:** Вы берете один носок, затем проверяете каждый другой носок в куче, чтобы узнать, подходит ли он. Затем берете второй носок и снова проверяете все остальные.
- **Сложность:** Вложенные циклы (**O(n²)**). Если у вас 1000 носков, это 1 000 000 проверок!

Вместо того чтобы сравнивать каждого с каждым, мы используем два индекса (указателя), которые перемещаются по массиву по умному алгоритму.

---

### Стратегия 1: Сходимость (Встреча посередине) ↔️

Это самая распространенная вариация. Вы ставите один указатель в **Начало** (`left`), а другой в **Конец** (`right`). Они движутся навстречу друг другу, пока не встретятся.

**Требование:** Массив обычно должен быть отсортирован.

#### Пример из жизни: Two Sum II (Sorted)

**Задача:** Найти два числа в отсортированном массиве `[2, 7, 11, 15]`, сумма которых равна 9.

**Логика:** Поскольку массив отсортирован, мы можем принимать решения:

- Сумма слишком маленькая? Нам нужно число побольше. Двигаем `left` вправо (увеличиваем).
- Сумма слишком большая? Нам нужно число поменьше. Двигаем `right` влево (уменьшаем).

```python
def two_sum_sorted(nums, target):
    left = 0
    right = len(nums) - 1

    while left < right:
        current_sum = nums[left] + nums[right]

        if current_sum == target:
            return [left, right]  # Нашли!

        elif current_sum < target:
            # Сумма 9, нам нужно 18.
            # Нужно число побольше. Двигаем левый вперед.
            left += 1

        else:
            # Сумма 20, нам нужно 18.
            # Нужно число поменьше. Двигаем правый назад.
            right -= 1

    return []
```

#### Пример 2: Валидный Палиндром 🪞

Является ли "racecar" палиндромом?

1. Проверяем `left` ('r') и `right` ('r'). Совпадают. Двигаем оба внутрь.
2. Проверяем `left` ('a') и `right` ('a'). Совпадают. Двигаем оба внутрь.
3. В конце концов, они встретятся посередине.

---

### Стратегия 2: Параллельные (Гонка) 🏎️

Здесь оба указателя начинают в начале (`index 0`), но они отслеживают разные вещи.
**Лучше всего для:** Слияния массивов или поиска пересечений.

#### Пример: Слияние двух отсортированных списков

**Дано** `A = [1, 4, 7]` и `B = [2, 3, 6]`. Мы хотим один отсортированный список.
**Логика:**
- Указатель `i` смотрит на A.
- Указатель `j` смотрит на B.
- Сравниваем `A[i]` и `B[j]`.
- Кто меньше? 1 или 2? 1 меньше. Добавляем 1 в наш результат и двигаем ТОЛЬКО указатель `i`.

---

### Стратегия 3: Чтение/Запись (In-Place Modification) ✍️

Это хитрый трюк. Мы используем два указателя на одном массиве.

- **Читатель (j):** Сканирует вперед, чтобы найти новые/валидные элементы.
- **Писатель (i):** Остается позади и перезаписывает массив валидными элементами.

#### Пример: Удаление дубликатов (Sorted)

**Вход:** `[1, 1, 2]` → **Выход:** `[1, 2]`
**Логика:**
1. Читатель видит 1. Это то же самое, что и предыдущее. Игнорируем.
2. Читатель видит 2. Это новое!
3. Писатель пишет 2 рядом с первой 1.

```python
def remove_duplicates(nums):
    # Writer (индекс вставки)
    i = 1

    # Reader (j) сканирует каждое число
    for j in range(1, len(nums)):
        # Если нашли НОВОЕ число (отличное от предыдущего)
        if nums[j] != nums[j - 1]:
            nums[i] = nums[j]  # Копируем его на позицию писателя
            i += 1             # Двигаем писателя вперед

    return i  # Новая длина
```

| :---------------- | :---------- | :------------------------- | :-------------------------------------------- |
| **Сходимость**    | Left, Right | Встречаются посередине (⇄) | Two Sum (Sorted), Проверка палиндрома         |
| **Параллельные**  | P1, P2      | Оба двигаются вправо (→)   | Слияние массивов, Поиск подпоследовательности |

  - Использовать **Hash Map** (O(n) время, O(n) память).
  - **Отсортировать массив** (O(n log n) время), затем использовать **Two Pointers** (O(1) память).

## Тема 10: Скользящее Окно (Sliding Window) 🪟

### Концепция

Один из самых элегантных паттернов в разработке алгоритмов. Берет задачу, которая кажется требующей вложенных циклов **O(n²)**, и решает её за один линейный проход **O(n)**.

---

### Аналогия: Картонная Рамка

Представьте длинную бумажную ленту с 1000 чисел. Вы вырезаете прямоугольное отверстие («Окно») в картоне шириной ровно на 3 числа.

1. Накладываете рамку на начало: видите `[10, 20, 30]`.
2. Сдвиг: Сдвигаете рамку на один шаг вправо.
3. Магия: Вам не нужно пересчитывать всю сумму
  - Число 10 покинуло поле зрения.
  - Число 40 вошло в него.
  - Новая Сумма = Старая Сумма – 10 + 40.

**Цель:** Переиспользовать предыдущую работу вместо того, чтобы начинать с нуля.

---

### Зачем это использовать?

Это превращает медленные **Вложенные Циклы** в быстрые **Линейные Сканирования**.

1. Способ "В лоб" (**O(n^2)**): "Посчитай сумму индексов 0-2. Затем сумму индексов 1-3. Затем 2-4..."
  *Проблема: Вы складываете одни и те же средние числа снова и снова. Это расточительство!*
2. Способ Скользящего Окна (**O(n)**): "Возьми предыдущую сумму. Вычти того, кто выпал. Прибавь того, кто только что вошел."

---

### Вариация 1: Окно Фиксированного Размера 📏

Используется, когда длина окна задана явно (например, задача *«Найти максимальную сумму любого подмассива размером k»* или «максимум суммы соседних элементов»).

**Пример:** Найти максимальную сумму 3 подряд идущих чисел в массиве `[2, 1, 5, 1, 3, 2]`, k=3.
**Шаги:**
1. **Инициализация:** Считаем сумму первых 3 чисел `[2, 1, 5]`. Сумма = 8.
2. **Сдвиг 1:** Убрать 2, Добавить 1. Окно `[1, 5, 1]`. Новая сумма = 8 - 2 + 1 = 7.
3. **Сдвиг 2:** Убрать 1, Добавить 3. Окно `[5, 1, 3]`. Новая сумма = 7 - 1 + 3 = 9. (**Новый Максимум!**)
4. **Сдвиг 3:** Убрать 5, Добавить 2. Окно `[1, 3, 2]`. Новая сумма = 9 - 5 + 2 = 6.

**Результат: 9.**

```python
def max_sum_fixed(nums, k):
    # 1. Считаем сумму первого окна
    current_sum = sum(nums[:k])
    max_sum = current_sum

    # 2. Сдвигаем окно с индекса k до конца
    for i in range(k, len(nums)):
        # i - это новый элемент, который входит
        # i - k - это старый элемент, который уходит
        current_sum = current_sum - nums[i - k] + nums[i]

        # 3. Обновляем глобальный максимум
        max_sum = max(max_sum, current_sum)

    return max_sum
```

### Вариация 2: Окно Динамического Размера (Акордеон) 🪗

Используется, когда задача просит найти **Самый длинный** или **Самый короткий** подмассив, удовлетворяющий условию. Окно растет и сжимается, как аккордеон или гусеница.

**Стратегия:**
1. **Расширение (Expand):** Двигайте указатель `right`, чтобы включить больше элементов (растяните аккордеон), пока условие не нарушится.
2. **Сжатие (Shrink):** Двигайте указатель `left`, чтобы убрать элементы (сжать аккордеон), пока условие снова не станет верным.

**Пример:** Найти самую длинную подстроку без повторяющихся символов (`"abcabcbb"`).
1. Окно `[a, b, c]`. Валидно. Расширяем (добавляем следующий символ).
2. Окно `[a, b, c, a]`. Невалидно! Дубликат 'a'.
3. Сжимаем: Удаляем слева, пока 'a' не уйдет. Удаляем первый 'a'.
4. Окно `[b, c, a]`. Валидно снова. Расширяем дальше.

Этот процесс похож на игру с аккордеоном: вы растягиваете его (expand), пока всё хорошо, и сжимаете (shrink), пока условие не нарушится.

```python
def length_of_longest_substring(s):
    seen = set()       # Множество для отслеживания символов в окне
    left = 0           # Левый указатель (начало окна)
    max_len = 0        # Максимальная длина найденной подстроки

    # Правый указатель "расширяет" окно
    for right in range(len(s)):

        # Пока наше окно невалидно (есть дубликат), сжимаем слева
        while s[right] in seen:
            seen.remove(s[left])  # Выгоняем символ слева
            left += 1             # Сдвигаем левую границу

        # Добавляем новый символ и обновляем макс. длину
        seen.add(s[right])
        # Размер окна = правый индекс - левый индекс + 1
        max_len = max(max_len, right - left + 1)

    return max_len
```

🧠 **Запомни паттерн:** «Если нужно найти подмассив/подстроку с определенным свойством — пробуй скользящее окно».

| **Динамическое**  | Растёт / Сжимается | Расширять справа, Сжимать слева  | Самая длинная подстрока, Минимальный размер подмассива |

2. **"Subarray"** (Подмассив) или **"Substring"** (Подстрока): Это подразумевает срез исходных данных (непрерывная часть).

## Тема 11: Префиксные Суммы (Prefix Sums) ➕

### Концепция

**Префиксная Сумма** — это техника, работающая как «Машина времени» для массивов. Она позволяет мгновенно отвечать на вопросы об истории данных.

Массив **Prefix Sum** — это список, где каждый элемент является текущей суммой (накопительным итогом) всех чисел до этой точки.

### Аналогия: Одометр Автомобиля 🚗

Представьте, что вы едете в путешествие. Вы не сбрасываете счетчик пробега каждый день. Вы просто позволяете ему крутиться.

- День 1: Вы проехали 100 км. Одометр: 100.
- День 2: Вы проехали 50 км. Одометр: 150.
- День 3: Вы проехали 200 км. Одометр: 350.

**Вопрос:** Сколько вы проехали в сумме за День 2 и День 3?

- **Медленный способ:** Сложить 50 + 200.
- **Способ Префиксной Суммы:** Взять итог на День 3 (350) и вычесть итог до начала Дня 2 (100).
- **350 - 100 = 250.**

---

### Зачем это использовать?

Представьте, что у вас есть массив из 10 000 чисел (например, ежедневные продажи за 30 лет).
Ваш босс задает 1000 разных вопросов, типа: «Каковы были общие продажи с 500-го по 800-й день?»

#### Способ «В лоб» O(n × m):

Вы пишете цикл от 500 до 800. Затем цикл от 20 до 100...
- **Результат:** Ваш сервер зависает. Выполнять цикл 1000 раз на огромном массиве — слишком медленно.

#### Способ Префиксной Суммы O(1):

Вы вычисляете бегущие суммы один раз. Теперь, чтобы найти сумму между любыми двумя точками, вы делаете всего одно вычитание.
- **Формула:** `Sum(i, j) = Prefix[j] - Prefix[i-1]`
- **Стоимость:** O(1) (Мгновенно).

---

### Как это работает (Пошагово)
Найдем сумму подмассива `[2, 5]` (индексы 2 и 3) из массива `[3, 1, 2, 5, 4]`.

#### Шаг 1: Построение Префиксного Массива
Мы проходим по массиву один раз, добавляя текущее число к предыдущей сумме.

- Индекс 0: 3
- Индекс 1: 3 + 1 = 4
- Индекс 2: 4 + 2 = 6
- Индекс 3: 6 + 5 = 11
- Индекс 4: 11 + 4 = 15
- **Prefix = [3, 4, 6, 11, 15]**

#### Шаг 2: Вычисление «Среза»
Нам нужна сумма индексов с 2 по 3 (значения 2, 5).

- **Общая Сумма** (до индекса 3): 11 (Включает 3, 1, 2, 5).
- **Нежелательная История** (до индекса 2): 4 (Это 3, 1).
- **Операция:** 11 - 4 = 7.
- **Проверка:** 2 + 5 = 7. Работает!

---

### Трюк с «Фиктивным Нулем» (Dummy Zero) 🛠️

Если вы попытаетесь вычислить `Sum(0, 3)`, вам нужно будет вычесть `Prefix[-1]`. Но `Prefix[-1]` означает конец списка в Python или ошибку в других языках!

Чтобы не проверять «Является ли это первым элементом?», мы добавляем **0** в начало нашего Префиксного Массива. Это действует как «бампер безопасности».

```python
def range_sum_query(nums, queries):
    # 1. Строим Prefix Sum (Размер N + 1)
    # Оригинал: [3, 1, 2]
    # Prefix:   [0, 3, 4, 6]
    prefix = [0] * (len(nums) + 1)

    for i in range(len(nums)):
        prefix[i + 1] = prefix[i] + nums[i]

    # 2. Отвечаем на запросы мгновенно
    results = []
    for start, end in queries:
        # Чтобы получить sum(start, end), берем P[end+1] - P[start]
        # +1 появляется из-за сдвига с фиктивным нулем.
        current_sum = prefix[end + 1] - prefix[start]
        results.append(current_sum)

    return results
```

### Продвинутый Паттерн: Сумма подмассива равна K 🧠

Это классическая задача LeetCode Medium.
**«Найти общее количество подмассивов, сумма которых равна ровно K.»**

Мы не можем использовать технику Sliding Window, потому что массив может содержать отрицательные числа (поэтому сумма не всегда растет). Мы должны использовать **Prefix Sum + Hash Map**.

**Логика:**
Если `Prefix[j] - Prefix[i] = K`, то `Prefix[j] - K = Prefix[i]`.

Мы сохраняем каждую префиксную сумму, которую видим, в Хеш-карту. По мере итерации мы проверяем: «Видел ли я раньше префиксную сумму, равную `Current_Sum - K`?»

```python
def subarray_sum(nums, k):
    count = 0
    curr_sum = 0
    # Map: {prefix_sum : сколько_раз_видели}
    # Инициализируем {0:1} для обработки случаев, когда подмассив начинается с индекса 0
    prefix_map = {0: 1}

    for num in nums:
        curr_sum += num

        # Магическая проверка формулы
        if (curr_sum - k) in prefix_map:
            count += prefix_map[curr_sum - k]

        # Добавляем текущую сумму в карту
        prefix_map[curr_sum] = prefix_map.get(curr_sum, 0) + 1

    return count
```

| **Брутфорс**          | Нет           | O(n) (Цикл)               | O(1)      |
| **Префиксная Сумма**  | O(n) (Сборка) | O(1) (Математика)         | O(n)      |

## Тема 12: Рекурсия (Recursion) 🔄

Каждый вызов рекурсии создает Stack Frame (кадр стека). В нем хранятся локальные переменные этой функции. Когда базовый случай срабатывает, кадры начинают схлопываться (удаляться) один за другим в порядке LIFO (как стопка тарелок про Стек).

Рекурсия — это метод, при котором функция вызывает саму себя, чтобы решить меньшую версию задачи.

Думайте об этом как о наборе **Русских Матрёшек**.

1. Вы открываете большую куклу. Внутри кукла поменьше.
2. Вы открываете меньшую куклу. Внутри еще меньше.
3. Вы продолжаете это делать, пока не дойдете до самой крошечной, цельной куклы, которую нельзя открыть.

**Концепция "Начала" (Inception):**

Это решение большой проблемы путем разбиения ее на более мелкие экземпляры той же самой проблемы.

---

### 2 Железных Правила Рекурсии

#### 1. Базовый Случай (Якорь) 🛑
Это "самая крошечная кукла". Это условие, которое останавливает рекурсию.

- **Без этого:** Функция вызывает саму себя вечно (Бесконечный цикл), пока у компьютера не закончится память. Это знаменитая ошибка **Stack Overflow** (Переполнение стека).

#### 2. Рекурсивный Шаг (Действие) 📈
Здесь функция вызывает саму себя с измененными входными данными.

- **Важно:** Входные данные должны приближаться к Базовому Случаю. Если вы вызовете `factorial(n)` внутри `factorial(n)`, вы никогда не сдвинетесь с места. Вы должны вызвать `factorial(n-1)`.

---

### Пример 1: Факториал (!)

**Математика:** 5! = 5 × 4 × 3 × 2 × 1.
**Рекурсивная логика:** 5! = 5 × 4!

```python
def factorial(n):
    # 1. Базовый случай: Знак "Стоп"
    if n <= 1:
        return 1

    # 2. Рекурсивный шаг: Уменьшение задачи
    # "Я пока не знаю ответа. Мне нужно спросить у n-1."
    return n * factorial(n - 1)
```

---

### Как это видит компьютер (Call Stack) 🥞

Помните Тему 7 (Стеки)? Вот где это важно. Когда вы вызываете `factorial(3)`, компьютер не просто знает ответ. Он ставит на паузу текущую функцию и добавляет новый "Список дел" в стек.

#### Фаза 1: Накручивание (Pushing)

1. `factorial(3)`: На паузе. Ждет `factorial(2)`.
2. `factorial(2)`: На паузе. Ждет `factorial(1)`.
3. `factorial(1)`: Базовый случай сработал! Возвращает 1.

#### Фаза 2: Раскручивание (Popping)

4. `factorial(2)` возобновляется: Возвращает 2 × 1 = 2.
5. `factorial(3)` возобновляется: Возвращает 3 × 2 = 6.
6. Готово.

---

### "Прыжок Веры" (Ментальный Хак) 🧠
Не визуализируйте весь стек в голове, используйте **Прыжок Веры**:

1. Предположите, что рекурсивный вызов `factorial(n-1)` магическим образом работает и дает правильный ответ.
2. Сосредоточьтесь только на том, как соединить этот ответ с вашим текущим числом n.

- **Не думайте:** *«Она идет вниз до 1, потом возвращает 1, потом возвращает 2...»*
- **Думайте:** *«Если у меня есть факториал 4, я просто умножаю его на 5.»*

---

### Скрытая Угроза: Фибоначчи и Сложность ⚠️
Посмотрим на последовательность Фибоначчи: 0, 1, 1, 2, 3, 5, 8...

**Формула:** `fib(n) = fib(n-1) + fib(n-2)`

```python
def fib(n):
    if n <= 1:
        return n
    return fib(n-1) + fib(n-2)
```

**Проблема:** Это чрезвычайно медленно **O(2ⁿ)**.
Чтобы вычислить `fib(5)`, он вычисляет `fib(3)` дважды. Чтобы вычислить `fib(100)`, потребуются триллионы лет.

---

### Решение: Мемоизация (Записная книжка) 📓

Не пересчитывайте. Запоминайте.
Сохраните результат `fib(3)` в Хеш-карте (Словаре). Перед вычислением проверьте карту. Это превращает **O(2ⁿ)** в **O(n)**.

---

### Рекурсия vs. Итерация (Циклы)

| Характеристика       | Рекурсия                              | Итерация (Циклы)                 |
|----------------------|---------------------------------------|----------------------------------|
| **Стиль кода**       | Чистый, элегантный, декларативный     | Детальные пошаговые инструкции   |
| **Память**           | Высокая O(N). Использует Стек вызовов | Низкая O(1). Константная память  |
| **Лучше для**        | Деревьев, Графов, Сортировки слиянием | Простых списков, Счетчиков       |
| **Риск краша**       | Stack Overflow (Переполнение)         | Infinite Loop (Зависание)        |

---

### Совет для LeetCode 💡

**Ловушка пространственной сложности:**
Даже если вы не создаете никаких переменных, рекурсивная функция использует **O(N)** Памяти из-за Стека вызовов (где N — глубина рекурсии).

* **Вопрос на интервью:** «Можете ли вы решить эту задачу с Древом за **O(1)** памяти?»
* **Ответ:** «Итеративно — да. Рекурсивно — нет (если не исключать глубину стека из расчета).»

## Тема 13: Хеш-таблицы (Словари/Dictionaries) 🗝️

Хеш-таблица (или **Hash Map**) — пожалуй, самая важная структура данных для собеседований. Если **Массивы — это «Фундамент», то Хеш-таблицы — это «Суперсила».**

Это структура данных, которая хранит данные в парах **Ключ-Значение** и обеспечивает **Мгновенный доступ (O(1))**.

---

### Аналогия: Волшебная Библиотека (без порядка) 📚

- **Подход Массива:** Чтобы найти «Гарри Поттера», вам придется пройти вдоль каждой полки, просматривая каждый корешок, пока не найдете книгу. Это займет вечность (**O(n)**).
- **Подход Хеш-таблицы:** Вы подходите к Волшебному Библиотекарю. Вы говорите «Гарри Поттер». Он щелкает пальцами и телепортирует вас прямо к Ряду 4, Полке 9, Слоту 2. Вы не ищете; вы просто прибываете на место.

---

### «Магия»: Хеш-функция 🪄

Как компьютер узнает, куда положить данные, не ища свободное место? Он использует **Хеш-функцию**.
Это математическая формула, которая берет **Вход (Ключ)** и превращает его в **Число (Индекс)**.

- Вход: «Apple» → Формула → Выход: Index 3
- Вход: «Banana» → Формула → Выход: Index 5

Когда вы захотите найти «Apple» позже, компьютер снова запустит формулу: «Apple» → 3. Он идет прямо в слот №3. Он никогда не смотрит на слоты 0, 1 или 2.

---

### Проблема Коллизий 💥

Иногда формула несовершена. Она может случайно выдать один и тот же индекс для двух разных ключей.

- «Apple» → Index 3
- «Grapes» → Index 3

Это называется **Коллизией**.
Если двум людям назначен один и тот же номер в отеле, что происходит?
**Решение (Chaining/Цепочки):** Мы помещаем Связный Список (или «ведро») внутри этого слота.

- Слот 3 содержит: `[Apple]` → `[Grapes]`
- Когда вы ищете «Grapes», компьютер идет в Слот 3, а затем быстро пробегает по короткому списку, чтобы найти нужное.

---

### Два Типа: Map vs. Set

#### 1. Hash Map (Словарь/Dictionary) 📖

Хранит **Ключ → Значение**.

- **Сценарий:** Хранение связей.
- **Пример:** «Мне нужно найти возраст пользователя по его имени.»
- **Код:** `phone_book = {"Alice": 5551234, "Bob": 5559876}`

#### 2. Hash Set (Множество) 🎒

Хранит **Только Ключи**. Без значений.

- **Сценарий:** Проверка существования (Видел ли я это раньше?).
- **Пример:** «Находится ли этот IP-адрес в черном списке?»
- **Код:** `visited_urls = {"google.com", "facebook.com"}`

```python
# Операции с Set в Python
my_set = set()
my_set.add(10)    # O(1)

if 10 in my_set:  # O(1) - Мгновенно!
    print("Нашел")
```

---

### Анализ Сложности

| Операция    | Массив (Неотсорт.)  | Хеш-таблица |
|-------------|---------------------|-------------|
| **Вставка** | O(1) (Append)       | O(1)        |
| **Поиск**   | O(n) (Медленно)     | O(1) (Мгновенно) |
| **Удаление**| O(n) (Медленно)     | O(1) (Мгновенно) |

> **Примечание:** В худшем случае (если ВСЕ ключи попадут в коллизию), сложность упадет до **O(n)**, но на интервью мы считаем ее **O(1)**.

### Частотный Массив / Словарь (Frequency Map / Counter) 📊

### Концепция

Паттерн **Frequency Map (Частотный массив/словарь)** — это стратегия сбора статистики, при которой мы подсчитываем количество упоминаний (частоту) каждого элемента в наборе данных. 

Вместо того чтобы для каждого элемента запускать вложенный цикл и искать его дубликаты (что даёт медленное решение **\(O(n^2)\)**), мы делаем всего один проход по данным. Мы фиксируем частоты в специальную структуру данных, превращая решение в быстрое линейное (**\(O(n)\)**).

### Аналогия: Коробки для сортировки почты

Представь, что перед тобой лежит гора писем для разных городов. «В лоб» (\(O(n^2)\)): ты берёшь первое письмо (например, в Москву), перебираешь всю гору, вытаскивая все письма в Москву. Потом берёшь письмо в Питер и снова перебираешь всю гору. 
«Частотный» подход (\(O(n)\)): ты ставишь перед собой коробки с названиями городов. Берёшь письмо из кучи всего один раз, смотришь на город и просто кидаешь в нужную коробку. В конце ты точно знаешь, сколько писем в какой город нужно отправить.

### Когда это использовать?

1. Когда нужно найти **дубликаты**, **уникальные элементы** или **самый частый/редкий** элемент в массиве или строке.
2. Когда нужно проверить, являются ли две строки **анаграммами** (состоят ли они из одинакового набора букв).
3. Когда нужно быстро находить «аномалии» и отклонения от правил (как в задаче №7 про Тайного Санту, где мы искали людей с `0` или `2` подарками).

### Реализация в Python (Два варианта)

В качестве «коробок» для подсчёта в Python используют либо обычный список `list` (если ключи — это небольшие числа/индексы от `0` до `N`), либо хэш-таблицу `dict` (если ключи — это строки или любые другие объекты).

#### Вариация 1: Чистый Python-словарь (Универсальный)
```python
def find_most_frequent_char(text):
    # Создаём пустой частотный словарь
    freq_map = {}
    
    # 1. Заполняем частоты за один проход O(n)
    for char in text:
        if char != " ":  # Игнорируем пробелы
            freq_map[char] = freq_map.get(char, 0) + 1
            
    # 2. Ищем символ с максимальной частотой
    most_frequent = None
    max_count = 0
    
    for char, count in freq_map.items():
        if count > max_count:
            max_count = count
            most_frequent = char
            
    return most_frequent, max_count
```

#### Вариация 2: Использование встроенного `collections.Counter` (Быстрый продакшен-вариант)
В реальных скриптах автоматизации (и в Яндекс Крауде) писать циклы для подсчёта вручную не нужно — для этого есть готовый и оптимизированный на уровне C инструмент.

```python
from collections import Counter

def check_anagram(str1, str2):
    # Counter автоматически превращает строку в частотный словарь вида {'a': 3, 'b': 1}
    # Сравнение двух Counter-ов работает за линейное время O(n)
    return Counter(str1) == Counter(str2)
```

### Анализ Сложности Операций

| Вариант реализации                | Время на запись | Время на чтение | Память           |
|-----------------------------------|-----------------|-----------------|------------------|
| **Вложенные циклы (Без паттерна)**| O(1)            | O(n^2)          | O(1)             |
| **Массив / Список флагов**        | O(1)            | O(1)            | O(N) (макс. N)   |
| **Хэш-мап (dict / Counter)**      | O(1) в среднем  | O(1) в среднем  | O(u) (уникальные)|

### Совет для LeetCode 💡

Если задача просит посчитать количество чего-либо, проверить уникальность или найти пересечения, твой первый кандидат — **Частотный словарь**. 
В Python всегда помни про `Counter` из модуля `collections`. Он экономит кучу времени на написании шаблонного кода. Метод `Counter.most_common(k)` мгновенно вернёт тебе `k` самых часто встречающихся элементов, что решает добрую треть Easy-задач на строки и массивы.

### Разбор задачи LeetCode: Two Sum 💡

**Задача:** Найти два числа в массиве `[2, 7, 11, 15]`, которые в сумме дают 9.
**Стратегия «Hash Map» O(n)**:

Вместо двух циклов (**O(n²)**), мы проходим по списку один раз. Мы используем Map, чтобы «запомнить», что мы видели.

**Трассировка:**

1. **Index 0 (Val 2):** Нам нужно 9 - 2 = 7. Есть ли 7 в карте? Нет. Сохраняем `{2: Index 0}`.
2. **Index 1 (Val 7):** Нам нужно 9 - 7 = 2. Есть ли 2 в карте? **ДА!**
3. **Результат:** Мы нашли пару (2, 7). Возвращаем индексы `[0, 1]`.

```python
def two_sum(nums, target):
    # Map хранит: {Число : Индекс}
    prev_map = {}

    for i, n in enumerate(nums):
        # Видели ли мы эту разницу раньше?
        diff = target - n

        if diff in prev_map:
            return [prev_map[diff], i]

        # Если нет, запоминаем текущее число на будущее
        prev_map[n] = i
```

### Совет для LeetCode 🧠

Если задача спрашивает о:

1. **"Частоте"** (Подсчитать, сколько раз встречается x) ⇒ Используйте Hash Map `{Item: Count}`.
2. **"Дубликатах"** (Проверить, существует ли x) ⇒ Используйте Hash Set.
3. **"Парах"** (Найти x и y) ⇒ Используйте Hash Map для хранения «дополнения» (Target - x).

> **Факты о хеш-таблицах:**
> 1. Длина всех хэш-ключей одинакова.
> 2. Индекс — это остаток от ключа.
> 3. При коллизии создаётся бакет для хранения совпадений по хэшу (связный список).

## Тема 14: Бинарный Поиск (Binary Search / Divide & Conquer) ✂️

### Концепция

Бинарный Поиск — это самый эффективный способ найти элемент в Отсортированном списке. Он работает путем многократного деления области поиска пополам.

### Аналогия: Игра «Угадай число» 🎲

Я загадываю число от 1 до 100. Вы должны его угадать.

- **Я:** (Тайно выбираю 75)
- **Вы:** «50»
- **Я:** «Мало.»

**Эффект:** Вы только что исключили числа 1–50. Вы не проверяли их по одному. Вы удалили половину вселенной мгновенно.

- **Вы:** «75»
- **Я:** «Правильно!»

Задавая всего **7 вопросов**, вы можете найти любое число от 1 до 100.
Задавая всего **30 вопросов**, вы можете найти любое число от 1 до 1 Миллиарда.

---

### Основной Алгоритм (Итеративный)

Мы используем три указателя:

1. **Left (l):** Начало текущего диапазона.
2. **Right (r):** Конец текущего диапазона.
3. **Mid (mid):** Середина.

```python
def binary_search(nums, target):
    left, right = 0, len(nums) - 1

    while left <= right:
        # Находим середину
        mid = (left + right) // 2

        # Случай 1: Нашли!
        if nums[mid] == target:
            return mid

        # Случай 2: Цель в правой половине
        elif nums[mid] < target:
            left = mid + 1  # Сдвигаем начало вперед

        # Случай 3: Цель в левой половине
        else:
            right = mid - 1  # Сдвигаем конец назад

    return -1  # Не найдено
```

---

### Главное Требование ⚠️

Бинарный Поиск работает **ТОЛЬКО** если массив **Отсортирован**.

- `[1, 3, 5, 9, 12]` ✅ Работает.
- `[5, 1, 9, 3, 12]` ❌ Не сработает. Сначала нужно отсортировать O(n log n) или использовать Линейный Поиск O(n).

---

### Сложность: Сила Логарифмов 📉

Мы называем это **Логарифмическим Временем O(log n)**.
Это невероятно быстро, потому что количество шагов растет очень медленно по сравнению с данными.

| Элементов (**n**)        | Шаги Линейного Поиска | Шаги Бинарного Поиска |
| :----------------------- | :-------------------- | :-------------------- |
| 100                      | 100                   | 7                     |
| 10,000                   | 10,000                | 14                    |
| 1,000,000 (1M)           | 1,000,000             | 20                    |
| 1,000,000,000 (1B)       | 1 Миллиард            | **30**                |

### Продвинутый Паттерн 1: Поиск Границ (Первое/Последнее вхождение)

Часто LeetCode не спрашивает «Есть ли здесь 5?». Он спрашивает **«Где первая 5?»** или **«Где последняя 5?»**.

- **Вход:** `[1, 2, 5, 5, 5, 9]`
- **Стандартный бинарный поиск** может вернуть индекс 3 (средняя 5). Нам нужен индекс 2 (первая 5).

**Техника:** Когда вы находите цель, не останавливайтесь. Сохраните индекс и продолжайте поиск в нужной половине (влево для первой, вправо для последней).

```python
def find_first_occurrence(nums, target):
    left, right = 0, len(nums) - 1
    result = -1

    while left <= right:
        mid = (left + right) // 2

        if nums[mid] == target:
            result = mid       # Записываем потенциальный ответ
            right = mid - 1    # Продолжаем искать СЛЕВА

        elif nums[mid] < target:
            left = mid + 1
        else:
            right = mid - 1

    return result
```

### Продвинутый Паттерн 2: Поиск по «Пространству Ответов» 🧠

Иногда массив не дается. Вы ищете число, удовлетворяющее условию, а не элемент в списке. Вы запускаете бинарный поиск по диапазону возможных значений ответа.

**Пример:** «Коко ест бананы» (Koko Eating Bananas). Найти минимальную скорость поедания k, чтобы успеть за H часов.
**Логика:**

- Если скорость 1 — слишком медленно.
- Если скорость 1,000,000 — достаточно быстро.
- Ответ находится где-то между 1 и 1,000,000. Запустите Бинарный Поиск по этому диапазону!

```python
def solve_answer_space(low, high):
    ans = high
    while low <= high:
        mid = (low + high) // 2

        if is_possible(mid):  # Вспомогательная функция проверки
            ans = mid         # Эта скорость подходит, попробуем медленнее?
            high = mid - 1
        else:
            low = mid + 1     # Слишком медленно, нужно быстрее

    return ans
```

В Python есть встроенная библиотека для этого. Используйте её на интервью, чтобы сэкономить время!

```python
import bisect

arr = [1, 3, 4, 4, 4, 6, 7]

# 1. Найти индекс для вставки (Левая/Первая позиция)

# Возвращает 2 (Индекс первой 4)

# 2. Найти индекс для вставки (Правая/Последняя позиция)

```

### Частый Баг: Переполнение (Overflow) 🪲

В таких языках, как C++ или Java, вычисление `mid = (left + right) / 2` может вызвать переполнение целого числа (Integer Overflow), если `left + right` больше максимального размера int (2³¹).

* **Безопасный способ:** `mid = left + (right - left) // 2`
* **Примечание:** Python обрабатывает большие числа автоматически, так что это не обязательно, но интервьюеры это любят.

## Тема 15: Основы сортировки ("Медленные" алгоритмы) 🐢

### Зачем учить "медленную" сортировку?

В современных языках есть встроенные функции сортировки (например, `.sort()` в Python), которые невероятно быстры (**O(n\log n)**). Однако понимание базовых алгоритмов **O(n^2)** важно, потому что:

1. Фундаментальная логика: Они учат вас манипулировать индексами массива и делать обмены (swaps).
2. Эффективность на малых данных: Для очень маленьких массивов (например, < 50 элементов) эти “медленные” алгоритмы часто быстрее сложных (как Merge Sort), потому что у них меньше накладных расходов.
3. Собеседования: Вас могут попросить “Отсортировать почти отсортированный массив” (здесь Insertion Sort — король).


### 1. Bubble sort (Сортировка пузырьком) 🫧

Работает по принципу «всплытия» самого большого элемента в конец списка на каждой итерации.

**Как это работает:**

1. Сравните индекс 0 и 1. Если `Left > Right`, обменяйте.
2. Перейдите к 1 и 2. Повторите.
3. После одного полного прохода самое большое число гарантированно окажется в самом конце.
4. Игнорируйте последний элемент (он отсортирован) и повторите для остальных.

**Пример трассировки:** `[5, 3, 8, 4, 2]`

1. Проход 1:
  - `[5, 3]` → Swap → `[3, 5, 8, 4, 2]`
  - `[5, 8]` → OK
  - `[8, 4]` → Swap → `[3, 5, 4, 8, 2]`
  - `[8, 2]` → Swap → `[3, 5, 4, 2, 8]` *(8 теперь зафиксировано в конце)*
2. Проход 2:
  - `[3, 5, 4, 2]`...

```python
def bubble_sort(arr):
    n = len(arr)
    for i in range(n):
        # Флаг оптимизации
        swapped = False

    # Последние i элементов уже отсортированы
        for j in range(0, n - i - 1):
            if arr[j] > arr[j + 1]:
                arr[j], arr[j + 1] = arr[j + 1], arr[j]
                swapped = True

    # Оптимизация: Если обменов не было, список отсортирован!
        if not swapped:
            break
    return arr
```

**Примеры не leetcode:**

```python
def bubble_sort(arr):
    n = len(arr)  # Узнаем длину списка

    # Внешний цикл: сколько раз нужно пройти по списку
    for i in range(n - 1):
        # Внутренний цикл: сравниваем соседние пары
        # С каждым шагом i «хвост» списка уже отсортирован
        for j in range(n - 1 - i):
            # Сравниваем соседние элементы
            if arr[j] > arr[j + 1]:
                # Меняем их местами, если левый больше правого
                arr[j], arr[j + 1] = arr[j + 1], arr[j]

    return arr
```

**Главные фишки:**

1. `n - 1 - i`: Это важная деталь. Мы вычитаем `i`, потому что после каждого прохода самый большой элемент в оставшейся части гарантированно оказывается в конце, и его больше не нужно проверять.
2. **Сравнение соседей:** В отличие от сортировки выбором (где мы искали минимум), здесь мы просто «двигаем» большие числа вправо через обмены с соседом.

**Пример с оптимизацией:**

```python
def bubble_sort_optimized(arr):
    n = len(arr)

    for i in range(n - 1):
        # Флаг: были ли перестановки в этом проходе?
        swapped = False

        for j in range(n - 1 - i):
            if arr[j] > arr[j + 1]:
                # Меняем местами, если порядок неверный
                arr[j], arr[j + 1] = arr[j + 1], arr[j]
                swapped = True  # Фиксируем, что перестановка была

        # Если за весь проход ни разу не сработал swap — список готов
        if not swapped:
            break

    return arr
```

### 2. Selection Sort (Сортировка выбором) 🔍

**Концепция:** Ищите во всем неотсортированном списке самое маленькое число (минимум) и меняйте его местами с началом.

**Как это работает:**
1. Начните с индекса 0. Сканируйте от 0 до end. Найдите минимум.
2. Поменяйте этот минимум с индексом 0.
3. Начните с индекса 1. Сканируйте от 1 до end. Найдите минимум.
4. Поменяйте этот минимум с индексом 1.

**Зачем использовать?** Это минимизирует количество Обменов (Swaps). Bubble sort меняет элементы постоянно; Selection sort меняет только один раз за проход. Это полезно, если «запись в память» стоит дорого (например, флэш-память).

```python
def selection_sort(arr):
    n = len(arr)
    for i in range(n):
        min_idx = i

    # Находим минимальный элемент в оставшейся части
        for j in range(i + 1, n):
            if arr[j] < arr[min_idx]:
                min_idx = j

    # Меняем найденный минимум с первым элементом
        arr[i], arr[min_idx] = arr[min_idx], arr[i]
    return arr
```

**Примеры реализации не leetcode:**

```python
def selection_sort(arr):
    n = len(arr)

    # Проходим по списку
    for i in range(n - 1):
        min_index = i

        # Ищем индекс самого маленького элемента в оставшейся части
        for j in range(i + 1, n):
            if arr[j] < arr[min_index]:
                min_index = j

        # Если нашли элемент меньше текущего, меняем их местами
        if min_index != i:
            # Меняем значения местами
            arr[i], arr[min_index] = arr[min_index], arr[i]

    return arr

# Пример использования:
my_list = [64, 25, 12, 22, 11]
sorted_list = selection_sort(my_list)
print(sorted_list)
# Вывод: [11, 12, 22, 25, 64]
```

### 3. Insertion Sort (Сортировка вставками) 🃏

**Концепция:** Сортируйте список так же, как вы сортируете игральные карты в руке. Вы берете новую карту и сдвигаете её назад в правильное место среди карт, которые вы уже держите.

**Как это работает:**
1. Предположим, элемент 0 отсортирован.
2. Возьмите элемент 1. Сравните с 0. Если меньше, поменяйте.
3. Возьмите элемент 2. Сдвигайте его влево, пока он не встанет на место.

**Суперсила:** Он **Адаптивный**. Если список почти отсортирован, **Insertion Sort** работает почти за время **O(n)**. Это невероятно для «онлайн-алгоритмов», где данные поступают потоком.

---

**Реализация:**

```python
def insertion_sort(arr):
    for i in range(1, len(arr)):
        key = arr[i]
        j = i - 1

        # Сдвигаем элементы arr[0..i-1], которые больше key,
        # на одну позицию вперед
        while j >= 0 and key < arr[j]:
            arr[j + 1] = arr[j]
            j -= 1
        arr[j + 1] = key
    return arr
```

---

### Сравнение и когда что использовать

| Алгоритм      | Лучший случай   | Худший случай | Память   | Примечание                  |
| :------------ | :-------------- | :------------ | :------- | :-------------------------- |
| **Bubble**    | **O(n)** (Опт.) | **O(n^2)**    | **O(1)** | Слишком много обменов.      |
| **Selection** | **O(n^2)**      | **O(n^2)**    | **O(1)** | Меньше всего обменов.       |
| **Insertion** | **$O(n)$**      | **O(n^2)**    | **O(1)** | Лучший для малых массивов.  |

---

### LeetCode Хаки и Советы 💡

#### Хак 1: Гибрид Insertion Sort - Встроенная в Python `.sort()` (Timsort)

**Гибридная природа:** Она использует **Merge Sort** для больших кусков, но переключается на
**Insertion Sort**, когда куски становятся маленькими (около 32-64 элементов).
**Почему?** Потому что Insertion Sort побеждает сложные алгоритмы на малых данных.

#### Хак 2: Частично отсортированные данные
Если в задаче сказано: *«У вас есть отсортированный массив, но 2 элемента перепутаны»* или *«Элементы находятся не дальше k позиций от их цели»*, используйте **Insertion Sort**.

Он будет работать за **O(n)** или **O(nk)**, что очень быстро.

#### Хак 3: Стабильность (Stability)
Стабильность означает, что если у вас есть два объекта с одинаковым значением (например, два человека с именем «Боб»), их исходный порядок сохраняется.

- **Стабильные**: Insertion sort, Bubble Sort
- **Нестабильные:** Selection Sort, Quick Sort

## Тема 16: Быстрые сортировки (Merge & Quick) 🚀

### Предел Скорости: Преодоление Барьера
- Базовые сортировки, которые мы изучили (Bubble, Insertion), занимают **O(n^2)** времени.
- “Быстрые Сортировки” (Merge, Quick) занимают **O(n log n)** времени.

**Большая ли это разница?**
Представьте, что мы сортируем 1 миллион элементов:

- Bubble Sort **O(n^2)**: ~1,000,000,000,000 операций.
  Время: Несколько Дней.
- Quick Sort **O(n log n)**: ~20,000,000 операций.
  Время: Меньше 1 Секунды.

---

### 1. Merge Sort (Сортировка Слиянием) 🧩

**Стратегия:** Разделяй и Властвуй (Divide and Conquer).
Она полагается на простой факт: очень легко слить два списка, которые уже отсортированы.

**Это принцип (парадигма) построения алгоритмов.**
1. Разбиваем одну большую и сложную задачу на несколько маленьких.
2. Решаем их по отдельности.
3. Склеиваем результаты.

**Сортировки, работающие по этому принципу:**

- **Merge Sort** (Сортировка слиянием) — самая наглядная реализация этого принципа.
- **Quick Sort** (Быстрая сортировка / Сортировка Хоара).

---

**Алгоритм:**

1. **Divide (Разделение):** Разрежьте список пополам. Затем разрежьте эти половины пополам. Продолжайте резать, пока в каждом списке не останется только 1 элемент. *(Список из 1 элемента технически «отсортирован»)*.
2. **Conquer (Слияние):** Возьмите два маленьких отсортированных списка и соедините («сшейте») их вместе в один большой отсортированный список.
3. **Repeat (Повторение):** Продолжайте сливать вверх, пока не получите один большой отсортированный список.

**Зачем использовать?** Она **Стабильна (Stable)** 🔒

Если вы сортируете список товаров по Цене, а затем по Рейтингу, Merge Sort сохранит порядок Цен для товаров с одинаковым Рейтингом. Именно поэтому `.sort()` в Python использует вариацию Merge Sort (называемую **Timsort**).

```python
def merge_sort(arr):
    if len(arr) > 1:
        mid = len(arr) // 2
        left_half = arr[:mid]
        right_half = arr[mid:]

        # Рекурсия: Сортируем половины
        merge_sort(left_half)
        merge_sort(right_half)

        # Шаг слияния: Собираем обратно
        i = j = k = 0
        while i < len(left_half) and j < len(right_half):
            if left_half[i] < right_half[j]:
                arr[k] = left_half[i]
                i += 1
            else:
                arr[k] = right_half[j]
                j += 1
            k += 1

        # Добавляем остатки...
        while i < len(left_half):
            arr[k] = left_half[i]
            i += 1
            k += 1

        while j < len(right_half):
            arr[k] = right_half[j]
            j += 1
            k += 1

    return arr
```

### Quick Sort (Быстрая Сортировка) ⚡️

Quick Sort тоже делит список, но делает основную работу до разделения, используя **Pivot** (Опорный элемент).

**Алгоритм:**

1. **Выбор Pivot:** Выберите рандомное число из массива (например, последнее).
2. **Partition (Разбиение):** Делим массив на 2 части:
   - Все числа меньше Pivot переносим Влево.
   - Все числа больше Pivot переносим Вправо.
3. **Рекурсия:** Повторите процесс для левой и правой части (подмассивов) рекурсивно.

---

1. Выбираем рандомный pivot.
2. Делим массив на 2.
3. В левый элементы < pivot, в правый > pivot.
4. Делим подмассивы и повтор рекурсивно.
5. Склеиваем все подмассивы.

---

**Проблема Pivot:** ⚠️
Если вы каждый раз выбираете самое маленькое или самое большое число в качестве pivot (например, сортируя уже отсортированный список), Quick Sort деградирует до **O(n²)**.

* **Решение:** случайный pivot или медиану из 3 чисел.

**LeetCode:**

```python
def quick_sort(arr):
    if len(arr) <= 1:
        return arr
    else:
        pivot = arr.pop()
        greater = []
        lower = []

        for item in arr:
            if item > pivot:
                greater.append(item)
            else:
                lower.append(item)

        return quick_sort(lower) + [pivot] + quick_sort(greater)
```

### Сравнение: Merge Sort vs Quick Sort

| Характеристика        | Merge Sort                          | Quick Sort                                    |
| :-------------------- | :---------------------------------- | :-------------------------------------------- |
| **Стратегия**         | Сначала раздели, потом слей         | Сначала отсортируй (Partition), потом раздели |
| **Сложность (Время)** | **O(n log n)** (Всегда)             | **O(n log n)** (Среднее), **O(n²)** (Худшее)  |
| **Сложность (Память)**| **O(n)** (Нужна доп. память)        | **O(log n)** (Мало памяти)                    |
| **Где используется**  | Python, Java (Объекты)              | C++, Java (Примитивы)                         |

### LeetCode Хак: Quick Select 💡

Это скрытая жемчужина.
**Задача:** «Найти K-й самый большой элемент в массиве.»
  - **Наивно:** Отсортировать массив **O(n log n)** и взять индекс k.
  - **Pro (Quick Select):** Используйте логику Partition из Quick Sort.

**Логика:**
Если вы разбили (Partition) массив, и Pivot приземлился на индекс k, поздравляем! Вы нашли K-й элемент, не сортируя остальную часть массива.

**Сложность:** O(n) среднем.

---

**Дополнительно:**

```python
def quick_sort(arr):
    # Базовый случай: если в списке 0 или 1 элемент, он уже отсортирован
    if len(arr) <= 1:
        return arr

    # Находим индекс опорного элемента (pivot) посередине
    pivot_index = len(arr) // 2
    pivot = arr[pivot_index]

    left = []
    right = []

    # Распределяем элементы по двум спискам
    for i in range(len(arr)):
        # Пропускаем сам опорный элемент по его индексу
        if i == pivot_index:
            continue

        if arr[i] < pivot:
            left.append(arr[i])  # Все, что меньше опорного — влево
        else:
            right.append(arr[i])  # Все, что больше или равно — вправо

    # Рекурсивно сортируем части и склеиваем: лево + опорный + право
    return quick_sort(left) + [pivot] + quick_sort(right)
```

**Через генераторы:**

```python
def quick_sort_short(arr):
    if len(arr) <= 1:
        return arr
    pivot = arr[len(arr) // 2]

    left = [x for i, x in enumerate(arr) if x < pivot and i != len(arr)//2]
    right = [x for i, x in enumerate(arr) if x >= pivot and i != len(arr)//2]

    return quick_sort_short(left) + [pivot] + quick_sort_short(right)
```

## Тема 17: Бинарные Деревья 🌱

Бинарное Дерево — это особый тип дерева со строгим правилом:

### Ключевая Терминология (Семейное Древо) 👥

- **Root** (Корень/Предок): Верхний узел.
- **Node** (Узел): Круг, содержащий данные.
- **Child** (Ребенок): Узел, подключенный ниже.
- **Parent** (Родитель): Узел, находящийся выше.
- **Leaf** (Лист): Узел, не имеющий детей (Дно/Конец дерева).
- **Subtree** (Поддерево): Любой узел и все его потомки образуют "маленькое дерево" внутри большого.

**У каждого узла может быть НЕ БОЛЕЕ ДВУХ детей:**
1. Левый Ребенок (Left Child)
2. Правый Ребенок (Right Child)

---

### Структура Кода

Мы определяем узел как в Двусвязном Списке:

```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val       # Данные
        self.left = left     # Указатель на левого ребенка
        self.right = right   # Указатель на правого ребенка
```

---

### Как "ходить" по Дереву (Обходы DFS) 🚶‍♂️

Вы не можете использовать простой цикл `for`, потому что дерево ветвится. Мы используем **Рекурсию** для исследования дерева. Существует 3 основных способа посетить каждый узел (Поиск в глубину).

#### 1. Pre-order Traversal (Я, Лево, Право)

**Логика:** "Я обрабатываю себя сначала, затем иду к левому ребенку, затем к правому."
**Порядок:** Root → Left → Right
**Сценарий:** Клонирование дерева (нужно создать родителя, прежде чем создавать детей).

```python
def preorder(root):
    if not root:
        return

    print(root.val)       # 1. ОБРАБОТАТЬ СЕБЯ
    preorder(root.left)   # 2. ИДТИ ВЛЕВО
    preorder(root.right)  # 3. ИДТИ ВПРАВО
```

#### 2. In-order Traversal (Лево, Я, Право)

**Логика:** "Я иду до упора влево сначала. Я обрабатываю себя, когда возвращаюсь. Затем иду вправо."
**Порядок:** Left → Root → Right
**Сценарий:** Бинарные Деревья Поиска (BST). Этот обход печатает числа в отсортированном порядке!

```python
def inorder(root):
    if not root:
        return

    inorder(root.left)    # 1. ИДТИ ВЛЕВО
    print(root.val)       # 2. ОБРАБОТАТЬ СЕБЯ
    inorder(root.right)   # 3. ИДТИ ВПРАВО
```

#### 3. Post-order Traversal (Лево, Право, Я)

**Логика:** "Я посещаю всех своих детей сначала. Себя я обрабатываю последним."
**Порядок:** Left → Right → Root
**Сценарий:** Удаление дерева (вы должны удалить детей, прежде чем сможете удалить родителя) или вычисление размера папки.

```python
def postorder(root):
    if not root:
        return

    postorder(root.left)   # 1. ИДТИ ВЛЕВО
    postorder(root.right)  # 2. ИДТИ ВПРАВО
    print(root.val)        # 3. ОБРАБОТАТЬ СЕБЯ
```

---

### Основные Алгоритмы Деревьев (Туториал) 🛠️. Патерн: Доверяй Рекурсии

#### 1. Максимальная глубина (Max Depth)

**Задача:** Сколько слоев в глубину у дерева?
**Базовый случай:** Если узел `None`, глубина 0.
**Рекурсивный шаг:** Моя глубина = 1 + max(глубина_слева, глубина_справа).

```python
def maxDepth(root):
    if not root:
        return 0

    left_h = maxDepth(root.left)
    right_h = maxDepth(root.right)

    return 1 + max(left_h, right_h)
```

#### 2. Одинаковые Деревья (Same Tree)

**Задача:** Выглядят ли два дерева (`p` и `q`) абсолютно одинаково?
**Логика:**
- Если оба `None` ⇒ `True`.
- Если одно `None` (а другое нет) ⇒ `False`.
- Если значения разные ⇒ `False`.
- Иначе, проверь совпадает ли `left` И совпадает ли `right`.

```python
def isSameTree(p, q):
    if not p and not q:
        return True
    if not p or not q:
        return False
    if p.val != q.val:
        return False

    return isSameTree(p.left, q.left) and isSameTree(p.right, q.right)
```

#### 3. Инвертировать Дерево (Invert Binary Tree) 🙃

**Задача:** Поменяйте местами каждого левого и правого ребенка.
**Логика:** Поменяй моих детей, затем скажи им поменять своих детей.

```python
def invertTree(root):
    if not root:
        return None

    # Swap
    root.left, root.right = root.right, root.left

    # Рекурсия
    invertTree(root.left)
    invertTree(root.right)

    return root
```

#### 4. Сумма Пути (Path Sum)

**Задача:** Есть ли путь от Корня до Листа, который в сумме дает `targetSum`?
**Логика:** Вычти мое значение из цели. Спроси детей: "Можете ли вы собрать новую цель?"

```python
def hasPathSum(root, targetSum):
    if not root:
        return False

    # Проверка: Я Лист И я завершаю сумму
    if not root.left and not root.right:
        return targetSum == root.val

    new_target = targetSum - root.val
    return hasPathSum(root.left, new_target) or hasPathSum(root.right, new_target)
```

---

### Анализ Сложности 📈

1. **Время:** O(n). Почти в каждой задаче с деревом вы посещаете каждый узел ровно один раз.
2. **Память:** O(h) (Высота дерева).
  - **Лучший случай (Сбалансированное):** Дерево похоже на треугольник. Высота log n. Память O(log n).
  - **Худший случай (Скошенное):** Дерево — прямая линия (Связный Список). Высота n. Память O(n) из-за стека рекурсии.

---

### Обход по Уровням (BFS) 🌊

Иногда нужно идти "Уровень за Уровнем" (Уровень 0, затем Уровень 1, затем Уровень 2).
Рекурсия (DFS) для этого плоха. Используйте **Очередь** (Тема 8)!

---

### Пример реализации кода

```python
from collections import deque

def levelOrder(root):
    if not root:
        return []
    queue = deque([root])
    results = []

    while queue:
        level = []
        for i in range(len(queue)):
            node = queue.popleft()
            level.append(node.val)
            if node.left:
                queue.append(node.left)
            if node.right:
                queue.append(node.right)
        results.append(level)

    return results
```

## Тема 18: Бинарные Деревья Поиска (BST) 🕵️‍♀️

### Бинарное дерево поиска - визуал

* Количество потомков всегда два.
* Левый потомок всегда меньше родителя.
* Правый потомок всегда больше родителя.

### Бинарное дерево - добавление элемента

1. Сравнение с значением корня.
2. Выбор стороны в ветке.
3. Проверка каждого узла < / >.
4. Пройти всю глубину и разместить.

**Реализация такая же как в связных узлах:**
- Ссылки на узлы вперёд/назад = ссылки на узлы лево/право.
- Голова (sll/dll) = корень (у дерева).

---

### Что делает дерево "Поисковым"?

Обычное бинарное дерево — это просто куча данных. Если вы хотите найти число 42, вам придется проверить каждый узел (**O(n)**), потому что оно может быть где угодно.

**Бинарное Дерево Поиска (BST)** — это высокоорганизованная структура. Оно следует строгому правилу, которое позволяет вам действовать как снайпер: вы можете отсекать половину оставшихся данных на каждом шаге.

### Золотое Правило 📜

**Для каждого узла в дереве:**

1. **Левое поддерево:** ВСЕ значения должны быть **меньше** узла.
2. **Правое поддерево:** ВСЕ значения должны быть **больше** узла.

> *Примечание: Это должно быть верно для **каждого** узла, а не только для корня!*

---

### Поиск в BST 🔍

Благодаря Золотому Правилу нам никогда не нужно «угадывать», куда идти.

**Сценарий:** Найти 12 в дереве с корнем 10.

1. Сравниваем 12 с Корнем (10).
2. 12 > 10? Да.
3. **Действие:** Идем Вправо. **Важно:** Мы мгновенно игнорируем все Левое поддерево. Мы знаем, что 12 там быть не может.
4. Следующий узел 15. Сравниваем 12 с 15.
5. 12 < 15? Да.
6. **Действие:** Идем Влево. Нашли 12!

**Реализация в коде:**

```python
def search_bst(root, val):
    # Базовый случай: Не нашли или Нашли!
    if not root or root.val == val:
        return root

    # Время выбора
    if val < root.val:
        return search_bst(root.left, val)  # Идем Влево
    else:
        return search_bst(root.right, val)  # Идем Вправо
```

---

### Вставка в BST ➕

Вставка — это просто Поиск, который заканчивается созданием нового узла.

**Цель:** Вставить 12 в дерево.
1. Ищите 12.
2. Когда вы попадете в `None` (пустое место), где 12 должно быть, создайте там узел.

**Код вставки:**

```python
def insert_bst(root, val):
    if not root:
        return TreeNode(val)  # Создаем узел здесь

    if val < root.val:
        root.left = insert_bst(root.left, val)
    elif val > root.val:
        root.right = insert_bst(root.right, val)

    return root
```

---

### Ловушка "Валидации" ⚠️

Самая популярная задача на интервью — **"Validate Binary Search Tree"**.

* **Ошибка новичка:** Проверка только непосредственных детей.
  - `if root.left.val < root.val < root.right.val ...`

* **Почему это не работает:** Посмотрите на это невалидное дерево:
  - Корень: 10
  - Правый ребенок: 15 (Верно > 10)
  - Правый-Левый внук: 6
  - **Ошибка:** 6 находится справа от 10, значит, оно должно быть больше, но это не так. Проверка только родителя 15 не поймает это глобальное нарушение.

**Правильное решение (Передача диапазона):**
Каждый узел должен вписываться в определенный диапазон `(min, max)`.

- Корень: `(-inf, +inf)`
- Идем Влево? Максимум становится значением родителя: `(-inf, 10)`
- Идем Вправо? Минимум становится значением родителя: `(10, +inf)`

**Код проверки валидности:**
```python
def isValidBST(root):
    def validate(node, lower_limit, upper_limit):
        if not node:
            return True

        # Проверяем, нарушены ли строгие границы
        if not (lower_limit < node.val < upper_limit):
            return False

        # Влево: ограничиваем верх. Вправо: ограничиваем низ.
        return (validate(node.left, lower_limit, node.val) and
                validate(node.right, node.val, upper_limit))

    return validate(root, float("-inf"), float("inf"))
```

---

### В чем разница BT & BST?

* **BST** — это инструмент для быстрого поиска, вставки и удаления отсортированных данных.
* **Обычное бинарное дерево** — это каркас. На его базе строятся не только BST, но и кучи, деревья отрезков (Segment Trees), синтаксические деревья и многое другое.

---

### Анализ Сложности 📈

| Операция    | Сбалансированное BST | Скошенное BST (Линия)  |
|-------------|----------------------|------------------------|
| **Поиск**   | **O(log n)**         | **O(n)**               |
| **Вставка** | **O(log n)**         | **O(n)**               |
| **Удаление**| **O(log n)**         | **O(n)**               |

---

### Что такое Скошенное Дерево?
Если вы вставляете числа по порядку `1, 2, 3, 4, 5`, каждое число идет вправо. Дерево превращается в **Связный Список**.

**Решение:** Реальные системы используют **Самобалансирующиеся Деревья** (AVL, Red-Black), чтобы автоматически вращаться и сохранять высоту log n. Вам не нужно кодить их на интервью, просто знайте, что они существуют.

### Совет для LeetCode 💡

**Магия In-Order Traversal:**
Если вы выполните **In-Order Traversal** (Лево → Корень → Право) на BST, результат будет **Отсортированным Массивом**.

> *Это самый простой способ решить задачу «Найти K-й наименьший элемент в BST». Просто сделайте обход и остановитесь на К-м числе!*

## Тема 19: Кучи (Приоритетные Очереди) ⛰️

### Что такое Куча?

**Куча (Heap)** — это специализированная древовидная структура данных, которая удовлетворяет **Свойству Кучи**.

В отличие от Бинарного Дерева Поиска (которое полностью отсортировано слева направо), Куча отсортирована лишь **частично (сверху вниз)**. Её волнует только одно: **Кто на вершине?**

---

### Два Вкуса 🍦

1. **Min-Heap:** Самое **маленькое** число всегда в Корне. Каждый родитель меньше своих детей.
2. **Max-Heap:** Самое **большое** число всегда в Корне. Каждый родитель больше своих детей.

---

### Аналогия: Отделение Неотложной Помощи 🚑

Представьте приемный покой больницы.

- **Очередь (FIFO):** Первый пришел — первый обслужен. Пациент с порезом пальца, пришедший в 8:00, попадает к врачу раньше пациента с сердечным приступом, пришедшего в 8:05. **Это плохо.**
- **Приоритетная Очередь (Heap):** Пациентов лечат на основе **тяжести состояния**. Пациент с сердечным приступом мгновенно «всплывает» в начало очереди, независимо от времени прибытия.

---

### Операции и Скорость ⚡️

**Ключевая цель Куч:** Быстрый доступ к экстремальному элементу (Мин или Макс).

| Операция   | Сложность     | Описание                                                  |
| :--------- | :------------ | :-------------------------------------------------------- |
| **Peek**   | **O(1)**      | Мгновенно. “VIP” всегда наверху.                          |
| **Push**   | **O(log n)**  | Добавить вниз, затем “всплыть” на нужное место.           |
| **Pop**    | **O(log n)**  | Удалить верх, переместить низ наверх, затем “погрузить”.  |
| **Search** | **O(n)**      | Медленно! Кучи НЕ предназначены для поиска произвольных элементов. |

---

### Модуль `heapq` в Python 🐍

В Python есть встроенный модуль `heapq`.  
**Важное замечание:** По умолчанию он реализует **Min-Heap**.

```python
import heapq

# 1. Создание кучи
nums = [5, 1, 9, 3]
heapq.heapify(nums)

# nums теперь переорганизован за O(n).
# Самый маленький элемент под индексом 0.
# Структура: [1, 3, 9, 5]

# 2. Получить минимальный (Peek)
print(nums[0]) # Вернет 1. O(1)

# 3. Добавить элемент (Push)
heapq.heappush(nums, 2) # Добавляет 2. O(log n)

# 4. Удалить минимальный (Pop)
smallest = heapq.heappop(nums)

# Вернет 1. Куча перебалансируется. O(log n)
```

---

### Хак: Как получить Max-Heap? 🤔

Поскольку в Python нет класса MaxHeap, мы используем математический трюк: **Умножаем на -1.**

- **Оригинал:** `[10, 20, 5]`
- **Храним:** `[-10, -20, -5]`
- **Самый маленький** — `-20`. Когда вы достаете его (pop), умножьте на -1 снова, чтобы получить 20.

```python
max_heap = []

heapq.heappush(max_heap, -10)
heapq.heappush(max_heap, -20)
heapq.heappush(max_heap, -5)

# Получить самый большой

largest = -1 * heapq.heappop(max_heap) # Вернет 20
```

### Реальные сценарии использования

1. **Планировщики задач:** Процессор выбирает задачу с наивысшим приоритетом для запуска.
2. **Алгоритм Дейкстры:** Поиск кратчайшего пути в графе требует всегда выбирать «ближайший» узел следующим.
3. **Слияние K отсортированных списков:** Объединение нескольких потоков данных (например, логов).

---

### Стратегия LeetCode: Top K Elements 🏆

**Задача:** «Найти K-й самый большой элемент в потоке/массиве.»

#### Подход 1: Сортировка (Наивно)
Отсортировать весь массив.
- Цена: **O(N log N)**. Слишком медленно для больших данных.

#### Подход 2: Min-Heap (Ход Профи)
Поддерживайте Min-Heap размером ровно **K**.

- Итерируясь, добавляйте числа в кучу.
- Если размер кучи стал **> K**, удалите самое маленькое (корень).
- **Логика:** Если вы храните только **K самых больших чисел**, то «самое маленькое» из этих **K** (корень) будет ровно **K-м самым большим** в общем списке.
- Цена: **O(N log K)**. Гораздо быстрее, когда **K** мало.

```python
def findKthLargest(nums, k):
    heap = []

    for n in nums:
        heapq.heappush(heap, n)

        if len(heap) > k:
            heapq.heappop(heap) # Удаляем самое маленькое из группы

    return heap[0] # Корень — это K-й самый большой
```

---

### 4 Важных Совета 💡

1. **«К-й Самый Маленький?»** Используйте Max-Heap (храните отрицательные). Размер K.
2. **«К-й Самый Большой?»** Используйте Min-Heap. Размер K.
3. **«Медиана потока?»** Используйте ДВЕ кучи! Max-Heap для левой половины (маленькие числа) и Min-Heap для правой (большие).
4. **Не ищите:** Никогда не проверяйте наличие `x` в куче через `if x in heap`. Это **O(N)**. Используйте Set, если нужен поиск.

---

### 3 Кодерских Хака 🛠️

1. **heapify быстр:** `heapq.heapify(list)` работает за **O(N)**, а не **O(N log N)**. Используйте для инициализации.
2. **heappushpop:** Если нужно добавить и сразу удалить, используйте `heapq.heappushpop(h, item)`. Это эффективнее двух вызовов.
3. **Кортежи работают:** Можно хранить кортежи `(приоритет, имя_задачи)`. Python сравнивает первый элемент. Отлично для объектов.

```python
# Сортировка кортежей

tasks = []

heapq.heappush(tasks, (1, "Критический Баг"))
heapq.heappush(tasks, (3, "Писать Доки"))
heapq.heappush(tasks, (2, "Рефакторинг"))

# Удалит (1, "Критический Баг") первым, т.к. 1 < 2 < 3

print(heapq.heappop(tasks))
```

## Тема 20: Графы (Паутина Всего) 🕸️

### Что такое Граф?

**Граф** — это просто коллекция вещей (**Узлов/Вершин**), соединенных линиями (**Ребрами**).

Если задуматься, **Дерево** — это просто специфический тип Графа (без циклов и только с одним путем между узлами). Граф убирает все правила: он может иметь петли, разрозненные части и множество путей между А и Б.

---

#### Два Основных Типа ✌️

1. **Неориентированный Граф:** Двусторонняя улица. Если **А** связано с **Б**, то **Б** связано с **А**.
    * *Пример:* Друзья в Facebook (Дружба взаимна).
2. **Ориентированный Граф:** Односторонняя улица. **А** указывает на **Б**, но **Б** может не указывать обратно.
    * *Пример:* Twitter/Instagram (Вы подписаны на Илона Маска, он на вас — нет).

---

#### 7 Примеров Графов из Реальной Жизни 🌍

1.  **Социальные сети:** Узлы = Люди, Ребра = Дружба.
2.  **Навигация (Google Maps):** Узлы = Перекрестки, Ребра = Дороги.
3.  **Интернет:** Узлы = Веб-страницы, Ребра = Гиперссылки.
4.  **Пререквизиты курсов:** Узлы = Предметы, Ребра = «Нужно сдать до».
5.  **Рекомендательные системы:** Узлы = Юзеры/Товары, Ребра = «Купил».
6.  **Графы зависимостей:** Узлы = Файлы кода, Ребра = Импорт.
7.  **Компьютерные сети:** Узлы = Серверы, Ребра = Кабели/WiFi.

---

### Как хранить Граф? 💾

В Python нет встроенного класса Graph. Нам нужно строить его самим.

#### 1. Матрица Смежности (Сетка)

Мы создаем 2D Массив (**V x V**). **1** означает связь, **0** — отсутствие.

*   **Плюс:** Мгновенный поиск (**O(1)**) проверки «Связано ли А с Б?».
*   **Минус:** Тратит кучу памяти (**O(V^2)**). Если у вас 1M пользователей, сетка 1M x 1M обрушит вашу RAM.

```python
# Матрица: 3 Узла (0, 1, 2)
# 0 связан с 1. 1 связан с 2.
matrix = [
    [0, 1, 0], # Узел 0
    [1, 0, 1], # Узел 1
    [0, 1, 0]  # Узел 2
]

# Проверка связи 0 и 2:
# if matrix[0][2] == 1: ...
```

#### 2. Список Смежности (Стандарт) 🏆
Это то, что вы будете использовать в **99%** интервью.

Мы используем Словарь, где **Key = Узел**, а **Value = Список Соседей**.
**Плюс:** Эффективно по памяти (**O(V + E)**). Вы храните только реальные связи.

```python
graph = {
    "A": ["B", "C"],
    "B": ["A", "D"],
    "C": ["A"],
    "D": ["B"]
}
```

---

#### 5 Топ Популярные Кейсы

1. **Кратчайший Путь (GPS):** Найти самый быстрый маршрут от А до Б (**BFS** или Дейкстра).
2. **Нетворкинг/Распространение:** Как быстро распространится вирус/слух? (**BFS**).
3. **Обнаружение Цикла:** Есть ли бесконечная петля в зависимостях? (**DFS**).
4. **Топологическая Сортировка:** В каком порядке мне проходить эти курсы? (Ориентированный Граф).
5. **Компоненты Связности:** Сколько "островов" существует в сетке? (Union Find или DFS).

---

#### 4 Важных Совета 💡

1. **Узлы не всегда 0, 1, 2:** Иногда узлы — это Строки ("JFK", "LHR"). Маппируйте их в целые числа, если нужно, или просто используйте Словарь.
2. **Двунаправленные Ребра:** Если задача говорит «неориентированный», не забудьте добавить ребро дважды: `A->B` и `B->A`.
3. **Набор Visited:** Всегда, ВСЕГДА используйте `visited` set. Если вы этого не сделаете, ваш алгоритм застрянет в цикле навсегда.
4. **Несвязные Графы:** Не думайте, что граф — это один большой кусок. Вам может понадобиться цикл, чтобы запустить DFS/BFS на каждом непосещенном узле, чтобы покрыть изолированные острова.

---

#### 3 Кодерских Хака 🛠️

##### Хак 1: Шаблон с `defaultdict`
Этот сниппет строит Список Смежности из сырого списка ребер мгновенно. Запомните его.

```python
from collections import defaultdict

edges = [[0, 1], [1, 2], [2, 0]]
graph = defaultdict(list)

for u, v in edges:
    graph[u].append(v)
    graph[v].append(u) # Уберите эту строку, если Граф Ориентированный!
```

##### Хак 2: Неявные Графы (Сетки)
Иногда "Граф" не дается явно, дается просто 2D Сетка `[[1,1],[1,0]]`.

- **Узлы:** Ячейки `(r, c)`.
- **Ребра:** Вверх, Вниз, Влево, Вправо.
- **Не стройте список смежности!** Просто вычисляйте соседей математически.

```python
# Поиск соседей в сетке
directions = [(0,1), (0,-1), (1,0), (-1,0)] # П, Л, В, Н

for dr, dc in directions:
    new_r, new_c = r + dr, c + dc
```

##### Хак 3: Трюк с "Количеством Узлов"

Если ограничения говорят **V < 15**, вы, скорее всего, можете использовать экспоненциальное решение (**O(2^V)**) или битовые маски. Если **V > 10,000**, вам нужно **O(V + E)**.

---

#### Как понять, что нужен Граф? 🕵️‍♂️

Задайте себе эти вопросы:
1. **Есть ли отношения?** (Друзья, соединенные города, пререквизиты).
2. **Это сетка?** (Острова, лабиринты, движение роботов).
3. **"Минимальное количество шагов?"** -> Это **BFS** на Графе.
4. **"Существует ли путь?"** -> Это **DFS** или **BFS**.
5. **"Группы" или "Компоненты"?** -> Это **Union Find** или **DFS**.

## Тема 21: Обход Графов (BFS vs. DFS) 🧭

### Проблема

Вас бросили в лабиринт (Граф). Вам нужно найти выход. Как вы будете его исследовать?

В отличие от Массива, где вы можете просто запустить цикл `for i in range(len(arr))`, у Графа нет начала и конца. У него есть петли, тупики и изолированные острова.

Существует две фундаментальные стратегии для обхода (посещения каждого узла) графа.

---

### 1. Поиск в ширину (BFS - Breadth-First Search) 🌊

**Стратегия:** Исследуйте соседа за соседом, слой за слоем.

Представьте, что вы бросили камень в спокойный пруд. Рябь расходится идеальными, расширяющимися кругами.

1. **Дистанция 0:** Сам камень (Стартовый узел).
2. **Дистанция 1:** Все непосредственные соседи.
3. **Дистанция 2:** Все соседи соседей.

- **Структура данных:** Очередь (Queue - FIFO: Первый вошел, Первый вышел).
- **Поведение:** "Широкий" поиск. Он сканирует область, как радар.
- **Суперсила:** Он **ВСЕГДА** находит **Кратчайший Путь** в невзвешенном графе. Поскольку он ищет послойно, в тот момент, когда вы касаетесь цели, вы гарантированно сделали минимальное количество шагов.

---

#### Шаблон кода: BFS Template 📝

Запомните это. Это используется в 30% всех задач уровня Medium/Hard на графы.

```python
from collections import deque

def bfs(graph, start_node): # 1. Инициализируем Очередь со стартовым узлом
    queue = deque([start_node])

    # 2. Отслеживаем посещенные, чтобы избежать циклов
    visited = set([start_node])

    # 3. Обрабатываем Очередь
    while queue:
        node = queue.popleft() # Удаляем С НАЧАЛА (FIFO)
        print(f"Посещаем: {node}")

        # 4. Добавляем непосещенных соседей
        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append(neighbor)
```

---

#### Примеры из реальной жизни

1. **GPS Навигация:** Поиск маршрута с наименьшим количеством поворотов.
2. **Социальные сети:** "Люди, которых вы можете знать" (Друзья Друзей = Дистанция 2).
3. **Веб-краулеры:** Google индексирует страницы слой за слоем от начального URL.
4. **Бродкастинг:** Отправка wifi сигнала на все ближайшие устройства.
5. **Сборка мусора:** Поиск всех активных объектов в памяти.

---

### 2. Поиск в глубину (DFS - Depth-First Search) 🤿

**Стратегия:** Идите так глубоко, как возможно, затем возвращайтесь (backtrack).

Представьте прохождение лабиринта по правилу **“держаться левой стены”**.

1. Вы выбираете путь и идете, пока не упретесь в тупик.
2. **Backtrack:** Вы возвращаетесь к последнему перекрестку.
3. **Branch:** Вы пробуете следующий доступный путь.

- **Структура данных:** Стек (Stack - LIFO) или Рекурсия (Стек вызовов).
- **Поведение:** "Глубокий" поиск. Он пронзает граф, как молния.
- **Суперсила:** Использует меньше памяти, чем BFS для очень широких графов. Отлично подходит для исследования всех возможных путей или принятия решений (как в шахматном ИИ).

---

#### Шаблон кода 1: Рекурсивный DFS (Элегантный) ✨

```python
visited = set()

def dfs_recursive(node, graph): # 1. Базовый случай (неявно обрабатывается проверкой visited)
    if node in visited:
        return

    # 2. Обработка узла
    visited.add(node)
    print(f"Посещаем: {node}")

    # 3. Рекурсия по соседям
    for neighbor in graph[node]:
        dfs_recursive(neighbor, graph)
```

---

#### Шаблон кода 2: Итеративный DFS (Стек) 📚

Иногда рекурсия упирается в лимит “Stack Overflow”. Вот как сделать это вручную.

```python
def dfs_iterative(graph, start_node):
    stack = [start_node] # Используем СПИСОК как стек
    visited = set()

    while stack:
        node = stack.pop() # Удаляем С КОНЦА (LIFO)

        if node not in visited:
            print(f"Посещаем: {node}")
            visited.add(node)

            # Добавляем соседей в стек
            for neighbor in graph[node]:
                if neighbor not in visited:
                    stack.append(neighbor)
```

---

#### Примеры из реальной жизни

1.  **Решение лабиринтов:** Поиск *любого* пути к выходу (не обязательно кратчайшего).
2.  **Решение головоломок:** Судоку, Кроссворды (Бэктрекинг — это DFS).
3.  **Обнаружение циклов:** Поиск бесконечных петель в зависимостях кода.
4.  **Топологическая сортировка:** Планирование задач, зависящих друг от друга.
5.  **Поиск пути в играх:** ИИ, решающий последовательность ходов.

---

### Сравнение: Битва Титанов ⚔️

| Характеристика       | BFS (Ширина)               | DFS (Глубина)         |
|----------------------|----------------------------|-----------------------|
| **Структура**        | Очередь (Линия)            | Стек (Рекурсия)       |
| **Движение**         | Слой за слоем              | Ныряние вглубь        |
| **Кратчайший путь?** | ДА (Гарантированно)        | НЕТ (Случайный путь)  |
| **Память**           | Высокая (Хранит весь слой) | Низкая (Хранит текущую глубину) |
| **Сложность кода**   | Чуть больше кода (Очередь) | Очень коротко (Рекурсия) |

---

### 4 Важных Совета для Интервью 💡

1. **Кратчайший Путь = BFS:** Если задача спрашивает "минимум шагов", "кратчайшее расстояние" или "минимальный уровень", **перестаньте думать**. Используйте BFS. DFS не может гарантировать кратчайший путь без проверки всех путей.
2. **Все Пути = DFS:** Если задача просит "напечатать все пути" или "найти, существует ли путь", DFS обычно проще написать рекурсивно.
3. **Задачи на Сетке (Grid):** 2D Сетка — это просто Граф, где у каждой ячейки `(r, c)` есть 4 соседа (Вверх, Вниз, Влево, Вправо). Вы можете использовать BFS/DFS на сетках так же, как на обычных графах.
4. **Разъединенные Компоненты:** Всегда предполагайте, что граф может быть разбит на острова. Оберните ваш BFS/DFS в цикл:

```python
for node in all_nodes:
    if node not in visited:
        bfs(node)
```

### 3 Кодерских Хака ️

#### Хак 1: Отслеживание Уровня в BFS
Чтобы отслеживать, на каком “слое” (дистанции) вы находитесь, добавьте вложенный цикл внутри `while queue`.

```python
step = 0
while queue:
    # Обрабатываем ВЕСЬ слой за раз
    for _ in range(len(queue)):
        node = queue.popleft()
        if node == target: return step
        # Добавляем соседей...
    step += 1
```

#### Хак 2: Восстановление Пути

Чтобы напечатать реальный путь (например, A -> B -> D), храните карту `parent: {child: parent}`. Когда достигнете цели, идите назад от Цели, используя карту, чтобы восстановить путь.

#### Хак 3: Двунаправленный BFS

Если нужно искать в ОГРОМНОМ графе (например, связь между двумя пользователями Facebook), запустите BFS от Источника и от Цели **одновременно**. Когда они встретятся посередине, путь найден. Это экспоненциально быстрее.

### Как понять, что нужен BFS/DFS? 🕵️‍️

1.  "Кратчайший путь / Мин. шагов / Ближайший" -> **BFS**.
2.  "Обход по уровням" -> **BFS**.
3.  "Компоненты связности / Острова" -> **DFS** (или BFS, но DFS чище).
4.  "Есть ли цикл?" -> **DFS**.
5.  "Перестановки / Подмножества / Комбинации" -> **DFS** (Бэктрекинг).

---

### Пример LeetCode: Количество Островов ️

**Задача:** Дана сетка из `'1'` (земля) и `'0'` (вода), посчитайте количество островов.
**Стратегия:** Итерируемся по сетке. Когда видим `'1'`, увеличиваем счетчик, затем запускаем **DFS**, чтобы “потопить” (посетить) весь остров, чтобы не посчитать его снова.

```python
def numIslands(grid):
    if not grid: return 0

    count = 0
    rows, cols = len(grid), len(grid[0])

    def dfs(r, c):
        # Базовый случай: Выход за границы или вода
        if r < 0 or c < 0 or r >= rows or c >= cols or grid[r][c] == '0':
            return

        # Помечаем как посещенное (Топим остров)
        grid[r][c] = '0'

        # Посещаем соседей
        dfs(r+1, c)
        dfs(r-1, c)
        dfs(r, c+1)
        dfs(r, c-1)

    for r in range(rows):
        for c in range(cols):
            if grid[r][c] == '1': # Нашли новый остров
                count += 1
                dfs(r, c) # Топим его полностью

    return count
```

## Тема 23: Жадные Алгоритмы (Greedy Algorithms) 🎯

### Концепция

Паттерн **Greedy (Жадный)** — это стратегия проектирования алгоритмов, при которой на каждом шаге принимается локально оптимальное (самое выгодное прямо сейчас) решение. Алгоритм никогда не оглядывается назад и не пересматривает прошлые шаги, надеясь, что сумма лучших локальных выборов приведёт к глобально лучшему результату.

Она превращает сложное переборное решение в быстрое линейное решение **O(n)** или **O(n \log n)** из-за сортировки.

### Аналогия: Покупка на распродаже

Представь, что тебе разрешили бесплатно забрать из магазина ровно 3 любые вещи. «Жадный» подход: ты просто идёшь вдоль полок, находишь 3 самые дорогие вещи по ценникам и забираешь их. Тебе не нужно просчитывать сложные комбинации — ты берёшь максимум здесь и сейчас.

### Когда это работает? (Два условия)

1. **Свойство жадного выбора:** Локально лучший выбор на текущем шаге гарантированно ведёт к глобальному оптимуму.
2. **Оптимальная подструктура:** Глобальная задача состоит из точно таких же подзадач меньшего размера.

### Главная проблема решения «В лоб» (Где жадность ломается)

Жадный алгоритм абсолютно **бесполезен**, если будущие шаги жёстко зависят от решений в прошлом. В таких случаях жадность уступает место Динамическому Программированию.

### Стратегия: Сортировка по весу / выгоде

#### Пример из жизни: Задача о рюкзаке (Knapsack Problem — Fractional)
Вам нужно набить рюкзак ограниченной вместимости предметами с разной стоимостью и весом так, чтобы унести как можно более дорогой груз. Предметы можно делить на части.

```python
def max_value_greedy(capacity, items):
    # items = [[стоимость, вес], ...]
    # Сортируем предметы по удельной стоимости (цена за 1 кг) в убывающем порядке
    items.sort(key=lambda item: item[0] / item[1], reverse=True)
    
    total_value = 0.0
    for price, weight in items:
        if capacity >= weight:
            # Забираем предмет целиком
            capacity -= weight
            total_value += price
        else:
            # Забираем только ту часть, которая влезет в остаток рюкзака
            total_value += price * (capacity / weight)
            break
            
    return total_value
```

### Совет для LeetCode 💡

Если в условии задачи просят найти **максимум/минимум чего-либо**, а ограничения по времени очень жёсткие ($O(n)$ или $O(n \log n)$), всегда сначала проверяй Жадный алгоритм. 
* Попробуй мысленно отсортировать входные данные по возрастанию/убыванию профита. 
* Если локальный выбор не ломает логику для следующих элементов — пиши жадный код через сортировку или один цикл `for`. Если ломает — сразу переключайся на Динамическое Программирование.
