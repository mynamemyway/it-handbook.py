## Основы Асинхронности в Python (Asyncio) ⏱️⚡

### 1. Главная концепция: Однопоточная конкурентность

Асинхронность в Python — это **НЕ** параллельное выполнение кода в несколько потоков или на разных ядрах процессора. 
Python выполняет асинхронный код **строго в одном потоке**.

**Суть концепции:** Пока одна задача ждет ответа от внешней системы (например, скачивает файл из интернета или ждет ответ от базы данных), процессор не простаивает. Он временно переключается на выполнение другой задачи. 
**Главная цель:** Эффективно утилизировать время **ожидания** (I/O Bound задачи).

#### Аналогия: Повар на кухне 👨‍🍳
**Синхронный повар:**
  1. Поставил чайник греться, смотрит на него в ожидании пока закипит.
  2. Чайник закипел — повар начал резать бутерброд. (Процессор заблокирован ожиданием).
**Асинхронный повар:**
  1. Поставил чайник греться.
  2. Пока чайник греется, он отошел резать бутерброд.
  3. Как только чайник засвистел, повар вернулся к нему. (Повар один, поток один, но задачи делаются конкурентно).

---

### 2. Главный движок: Event Loop (Цикл событий) 🔄

Вся асинхронность держится на **Event Loop**. Это бесконечный цикл внутри Python, который управляет задачами.
1. Он берет задачу из списка и запускает её.
2. Как только задача говорит: *Я жду ответ от сервера*, Event Loop откладывает её в сторону.
3. Он берет следующую задачу.
4. Как только отложенная задача получила ответ, Event Loop возвращает её в работу.

---

### 3. Что такое asyncio и asyncio.sleep(1)

**asyncio** — это встроенный модуль (библиотека) в Python (через import asyncio). Внутри него написан движок асинхронности: там Event Loop и вспомогательные инструменты.
**asyncio.sleep(1)** — это асинхронная функция (корутина), написанная создателями Python внутри модуля asyncio.
**await asyncio.sleep(1)** — это вызов этой асинхронной функции с передачей управления обратно в Event Loop.

### 4. Чем асинхронный await отличается от обычного вызова функции по очереди?

В обычном (синхронном) коде, если Функции А нужны данные от Функции Б, мы просто вызываем Функцию Б внутри Функции А. Компьютер ждет выполнения Функции Б, получает данные и идет дальше. Все делается по очереди.

В чем же тогда разница?
Разница в том, ЧТО делает компьютер, пока он ждет.

Когда мы вызываем обычную (синхронную) функцию, которая идет в интернет или «спит», она полностью блокирует весь поток кода. Никакой другой код в программе в этот момент выполняться физически не может.

Пример:
Представь, что у нас есть сайт (например, интернет-магазин), и 3 разных пользователя одновременно зашли на него и нажали кнопку «Посмотреть баланс». Чтобы узнать баланс, нужно сделать запрос к базе данных, который идет ровно 1 секунду.

#### Сценарий А: Синхронный вызов (Обычные функции по очереди)

```python
import time
def get_balance(user_id):
    time.sleep(1)  # Имитируем запрос к базе. Поток ЗАМОРОЖЕН на 1 секунду!
    return 100
def handle_requests():
    # 3 пользователя зашли одновременно
    get_balance("Юзер_1")  # Компьютер застыл на 1 секунду. Юзер 2 и 3 ждут.
    get_balance("Юзер_2")  # Прошла 1 секунда. Компьютер снова застыл. Юзер 3 ждет.
    get_balance("Юзер_3")  # Прошло 2 секунды. Наконец-то дошла очередь.
```

* Итог: Третий пользователь ждал 3 секунды, чтобы просто увидеть свой баланс! Потому что пока выполнялся первый вызов, вся программа стояла «на паузе».

#### Сценарий Б: Асинхронный вызов (async / await)

```python
import asyncio
async def get_balance_async(user_id):
    # await говорит: "Я засыпаю на 1 секунду, но ПОТОК НЕ БЛОКИРУЮ. 
    # Event Loop, пока я жду, дай процессору поработать над другими задачами!"
    await asyncio.sleep(1) 
    return 100
async def main():
    # Запускаем все три запроса одновременно
    await asyncio.gather(
        get_balance_async("Юзер_1"),
        get_balance_async("Юзер_2"),
        get_balance_async("Юзер_3")
    )
```

**Как это сработает в памяти:**
1. Компьютер заходит в get_balance_async для Юзера 1, видит await asyncio.sleep(1). Он отправляет запрос в базу данных и тут же бросает эту функцию, переключаясь назад в Event Loop.
2. Event Loop мгновенно берет запрос Юзера 2. Заходит в функцию, видит await, отправляет второй запрос в базу и снова возвращается в Event Loop.
3. То же самое происходит для Юзера 3.
4. В итоге в воздухе одновременно висят 3 запроса к базе данных. Через 1 секунду они одновременно возвращают ответ.
* Итог: Все 3 пользователя получили свой баланс ровно через 1 секунду! Никто никого не ждал.

#### Резюме для понимания:

- Обычный вызов внутри функции — это цепочка. Пока «дочерняя» функция не сделает свою работу (даже если она просто тупо ждет ответа от сервера), вся программа ждёт.
- Асинхронный вызов через await — это умное переключение. Если функция понимает, что сейчас ей делать нечего (она ждет ответа от сети/базы/таймера), она добровольно отдает процессорное время другим функциям.

### 5. Когда асинхронность НУЖНА и НЕ НУЖНА в реальной разработке 🛠️

Главное правило: Асинхронность эффективна только для **I/O-bound** задач (задач ввода-вывода), где процессор большую часть времени **ждет** ответа от внешних ресурсов.

#### ✅ Когда асинхронность нужна:

1. **Запросы к Базе Данных (Даже если она на том же сервере)**
   * *Что происходит:* Твой код делает запрос `SELECT * FROM users`. Процессор работает в миллиарды раз быстрее, чем жесткий диск (SSD) ищет файлы базы данных. 
   * *Профит:* Через `await db.execute()` процессор отправляет запрос и мгновенно переключается на обработку других пользователей, пока диск готовит ответ.
2. **Запросы к внешним API**
   * *What происходит:* Отправка сетевого запроса в Телеграм-бот, платежную систему (Stripe/ЮKassa) или сервис погоды.
   * *Профит:* Сервер отправил сетевой пакет через интернет и ждет ответа полсекунды. Это вечность для процессора. Асинхронность утилизирует это время простоя.
3. **Чтение и запись тяжелых файлов**
   * *Что происходит:* Пользователь загружает на твой сервер аватарку или видео.
   * *Профит:* Пока сетевая карта принимает файл по кусочкам и пишет его на диск, асинхронный сервер не блокируется, а параллельно принимает текстовые сообщения от других юзеров.
4. **Веб-сокеты (Чаты и Онлайн-игры)**
   * *Что происходит:* 1,000 пользователей одновременно сидят в чате. Они ничего не пишут, а просто держат открытую страницу и ждут сообщений.
   * *Профит:* Синхронный сервер выделил бы под каждого юзера целый поток ОС и «умер» бы от нехватки памяти. Асинхронный Event Loop легко держит десятки тысяч таких «спящих» соединений в одном потоке.

---

#### Когда асинхронность НЕ нужна (вредна):

Если сервер выполняет операции **сам внутри себя**, используя только чистую силу процессора — это **CPU-bound** задачи. В них фазы ожидания нет, процессор занят на 100%.

1. **Тяжелые математические вычисления и алгоритмы**
   * *Пример:* Подсчет хэша пароля, сжатие/обработка картинок в памяти, сортировка массива на миллион элементов или циклы в алгоритмах LeetCode.
2. **Почему здесь асинхронность сделает код МЕДЛЕННЕЕ?**
   * Процессор загружен вычислениями каждую миллисекунду. Ему некогда переключаться. Асинхронный код не даст никакого ускорения, но программа станет медленнее, потому что Event Loop будет тратить лишние ресурсы на менеджмент и переключение задач.

> **Маркер для собеседования:** 
> «Асинхронность нужна там, где есть **ожидание** внешних ресурсов (Сеть, База Данных, Диск). Там, где нужно чисто **считать процессором** — асинхронность не работает, для этого используют **мультипроцессинг** (Multiprocessing) — запуск кода на разных ядрах процессора».

### 6. Разница между `async` и `await` 🧱

Это два главных ключевых слова, которые работают только в паре.

#### 1. Ключевое слово `async` (Объявление)
Ставится перед `def` и превращает обычную функцию в **корутину** (coroutine / асинхронную функцию).
**Зачем нужна:** Она сообщает Python: *Внутри этой функции будет происходить асинхронное ожидание. Не выполняй её как обычную функцию*.
**Особенность:** Если просто вызвать такую функцию в коде: `my_async_func()`, она **не выполнится**. Она просто вернет объект корутины (чертеж задачи). Чтобы она запустилась, её нужно передать в Event Loop.

#### 2. Ключевое слово `await` (Точка переключения)
Ставится строго **внутри** асинхронных функций перед вызовом других асинхронных функций.
**Зачем нужна:** Это маркер для Event Loop. Буквально переводится как: *Я здесь засыпаю, жду ответ. Переключись на другие задачи, а когда вернется результат, продолжи выполнение с этой же строчки*.
**Ограничение:** Нельзя использовать `await` внутри обычной синхронной функции. Будет ошибка синтаксиса.

#### 3. Как взаимодействуют `async` и `await`:
  1. `async def` — это маркер для интерпретатора: «Внимание, эта функция умеет делать паузы и отдавать управление другим задачам». Когда ты вызываешь такую функцию, она не запускается сразу, а возвращает объект-обещание (корутину).
  2. `await` — это ключевая точка паузы. Ты ставишь её только перед операциями, которые заставляют скрипт ждать внешних данных (IO-bound): запрос к API Яндекса, чтение тяжелого файла, запрос к базе данных.
  3. Когда выполнение доходит до await, текущая функция «засыпает», а управление возвращается в Event Loop (цикл событий). Event Loop смотрит: «Так, пока эта функция ждет ответа от сервера, какая еще задача готова поработать?» — и запускает другую.

### 7. Базовый шаблон кода на Python 🐍

```python
import asyncio
import time

# 1. Объявляем асинхронную функцию (корутину)
async def fetch_data(task_id, delay):
    print(f"Запрос {task_id} отправлен...")
    
    # Имитируем реальное ожидание сети (нельзя использовать time.sleep, он заблокирует поток!)
    # await отдает управление обратно в Event Loop
    await asyncio.sleep(delay) 
    
    print(f"--> Запрос {task_id} ПОЛУЧЕН!")
    return f"Данные {task_id}"

async def main():
    start_time = time.time()
    
    # asyncio.gather запускает несколько корутин одновременно в Event Loop
    results = await asyncio.gather(
        fetch_data(1, 2),  # Задача 1 ждет 2 секунды
        fetch_data(2, 3),  # Задача 2 ждет 3 секунды
        fetch_data(3, 1)   # Задача 3 ждет 1 секунду
    )
    
    print(f"Все результаты: {results}")
    print(f"Затрачено времени: {time.time() - start_time:.2f} сек")

# Точка входа: запускает Event Loop и передает ему главную функцию
asyncio.run(main())
```

**Вывод в консоли:**
```text
Запрос 1 отправлен...
Запрос 2 отправлен...
Запрос 3 отправлен...
--> Запрос 3 ПОЛУЧЕН!  (через 1 сек)
--> Запрос 1 ПОЛУЧЕН!  (через 2 сек)
--> Запрос 2 ПОЛУЧЕН!  (через 3 сек)
Все результаты: ['Данные 1', 'Данные 2', 'Данные 3']
Затрачено времени: 3.00 сек  (А не 2 + 3 + 1 = 6 секунд, как в синхронном коде!)
```

### 8. Краткая шпаргалка (Q&A)

**Асинхронность ускоряет математические вычисления (CPU-bound)?**
  - Нет. Если функция долго считает факториал или крутит циклы, асинхронность не поможет, так как поток всего один и он будет занят вычислениями. Повару некогда отвлекаться.
**Что такое корутина (Coroutine)?**
  - Это функция, объявленная через `async def`, выполнение которой можно приостановить (через `await`) и возобновить позже с того же места.
**Что будет, если в асинхронном коде вызвать синхронный `time.sleep(5)`?**
  - Он заблокирует весь поток целиком на 5 секунд. Event Loop «застынет», и ни одна другая асинхронная задача в этот момент не выполнится. Нужно использовать только `await asyncio.sleep(5)`.
