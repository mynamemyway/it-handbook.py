# SQL Style Guide — Шпаргалка

## 1. Именование

| Правило                                      | Пример                      | Комментарий                              |
|----------------------------------------------|-----------------------------|------------------------------------------|
| `snake_case`, только буквы/цифры/`_`         | `first_name`, `order_total` | Никогда `camelCase`, никогда `tbl_`/`sp_`|
| Имя начинается с буквы, не заканчивается `_` | `staff`, не `_staff_`       | —                                        |
| Избегать сокращений                          | `first_name`, не `fn`*      | *кроме псевдонимов в запросе             |
| Уникально в рамках схемы                     | —                           | Проверять по списку reserved words  СУБД |

### Таблицы
- Собирательное / множественное: `staff` > `employees`, `services` > `cars_mechanics`
- Имя таблицы **≠** имя любого её столбца
- Без префиксов `tbl_`, без венгерской нотации

### Столбцы
- Всегда **единственное число**: `employee`, не `employees`
- Не использовать `id` как имя первичного ключа → `employee_id`
- Имя столбца **≠** имя таблицы

### Псевдонимы
- Всегда через `AS`
- Короткие, из первых букв: `staff AS s`
- Для агрегатов — осмысленное имя: `SUM(amount) AS total_amount`

### Суффиксы столбцов
`_id` · `_status` · `_total` · `_num` · `_name` · `_seq` · `_date` · `_tally` · `_size` · `_addr`

## 2. Ключевые слова и синтаксис

- **UPPERCASE** для всех ключевых слов: `SELECT`, `FROM`, `WHERE`, `JOIN`, `ON`, `GROUP BY`
- Полный вариант вместо сокращённого: `ABSOLUTE`, не `ABS`
- Стандарт SQL > vendor-specific функции (переносимость)

### Операторы и условия
- `BETWEEN` вместо пары `AND`
- `IN (...)` вместо цепочки `OR`
- `CASE` для условной интерпретации значений
- Избегать `UNION` и временных таблиц без необходимости

```sql
SELECT model_num
  FROM phones AS p
 WHERE p.release_date > '2014-09-30';
```

## 3. Форматирование

> ⚠️ **Спорный момент.** Холиуэлл выравнивает ключевые слова по **правому** краю
> («коридор»). Современный мейнстрим (Google SQL, dbt, sqlfluff) — по **левому**.
> Оба варианта валидны, но в команде выбирайте один и фиксируйте в конфиге линтера.

### Левое выравнивание (современный дефолт)

```sql
SELECT
    a.title,
    a.release_date,
    a.recording_date
FROM albums AS a
WHERE a.title = 'Charcoal Lane'
   OR a.title = 'The New Danger'
ORDER BY a.release_date;
```

### Правое выравнивание (классика Холиуэлла)

```sql
SELECT a.title, a.release_date
  FROM albums AS a
 WHERE a.title = 'Charcoal Lane'
    OR a.title = 'The New Danger';
```

### Переносы строк
- После `;` — новый запрос
- Перед `AND` / `OR`
- После каждого основного ключевого слова
- После запятой при логических группах столбцов

### Пробелы
- Вокруг `=`
- После `,`

### JOIN

```sql
SELECT r.last_name
FROM riders AS r
INNER JOIN bikes AS b
    ON r.bike_vin_num = b.vin_num
   AND b.engine_tally > 2
INNER JOIN crew AS c
    ON r.crew_chief_last_name = c.last_name
   AND c.chief = 'Y';
```

### Подзапросы и CTE

Подзапрос — с тем же форматированием внутри.
Закрывающая `)` на новой строке под открывающей `(`.

> 🔑 **Дополнение к оригиналу:** в современном SQL активно используйте **CTE**
> (`WITH ... AS`) вместо вложенных подзапросов — читаемость выше, отладка проще.

```sql
WITH confirmed AS (
    SELECT last_name, championship_date
    FROM champions
    WHERE confirmed = 'Y'
)
SELECT r.last_name,
       MAX(c.championship_date) AS last_championship_year
FROM riders AS r
INNER JOIN confirmed AS c ON c.last_name = r.last_name
GROUP BY r.last_name;
```

## 4. `CREATE TABLE`

### Структура и порядок

```sql
CREATE TABLE staff (
    PRIMARY KEY (staff_num),          -- ключ первым
    staff_num      INT(5)       NOT NULL,
    first_name     VARCHAR(100) NOT NULL,
    pens_in_drawer INT(2)       NOT NULL,
    CONSTRAINT pens_in_drawer_range
        CHECK (pens_in_drawer BETWEEN 1 AND 99)
);
```

### Правила
- Отступ внутри `CREATE` — **4 пробела**
- `PRIMARY KEY` → первым
- Ограничение столбца → сразу под столбцом
- Табличные ограничения → в конце
- `ON DELETE` перед `ON UPDATE` (алфавитный порядок)
- `CHECK()` — отдельное именованное ограничение
- Значение `DEFAULT` → после типа, перед `NOT NULL`
- Тип `DEFAULT` = тип столбца

### Типы данных
- Стандартные типы > vendor-specific
- Для точной арифметики: `NUMERIC` / `DECIMAL`, **не** `FLOAT` / `REAL`
- Даты: **ISO 8601** → `YYYY-MM-DD HH:MM:SS`

### Ключи
- Уникальность, неизменность, простота
- Одинаковый тип данных во всей схеме
- Обоснованный выбор — не «потому что `id`»

## 5. Антипаттерны

| ❌ Не делать                                            | ✅ Вместо этого                                    |
|---------------------------------------------------------|----------------------------------------------------|
| `camelCase` в именах                                    | `snake_case`                                       |
| Префиксы `tbl_`, `sp_`                                  | Чистые имена                                       |
| Значения и единицы в разных столбцах                    | Один столбец + `CHECK()`                           |
| Паттерн EAV                                             | Специализированное хранилище (JSONB, document DB)  |
| Разнесение одной логической таблицы по времени/географии| Одна таблица + индекс                              |
| ООП-наследование в схеме                                | Реляционная модель                                 |
| Vendor-specific типы данных                             | ANSI SQL типы                                      |
