## docstrings: Google Style vs NumPy Style (с учетом стандартов PEP 257 и PEP 8)

Главное отличие между ними — **визуальное оформление блоков**:
* **Google Style** — типы и описания аргументов пишутся в одну строку с использованием двоеточия и отступов. Он более компактный и аккуратный.
* **NumPy Style** — под каждое имя аргумента выделяется отдельная строка, а названия секций подчеркиваются дефисами. Он более размашистый, но его легче читать, если описания параметров очень длинные.

---

### Стандарты PEP 257 и PEP 8 для отступов и пустых строк

Для того чтобы docstrings успешно обрабатывались линтерами (`pydocstyle`, `flake8`) и генераторами документации (`Sphinx`), необходимо строго соблюдать правила разметки, зафиксированные в **PEP 257** и **PEP 8**:

1. **Правило первой пустой строки (PEP 257):** В многострочном docstring первая строка — это всегда краткое однострочное описание (summary). Сразу после него **обязательно должна идти одна пустая строка**.
2. **Правило закрывающей кавычки (PEP 257):** В многострочных docstrings функций, методов и классов закрывающая кавычка `"""` должна находиться на отдельной строке, перед которой **пустая строка НЕ ставится**. Исключение: в docstring модуля или пакета пустая строка перед закрывающей кавычкой допускается, но не является обязательной.
3. **Правило выравнивания отступов (PEP 8):** Весь текст внутри docstring (кроме первой строки) должен быть выровнен строго по уровню открывающих кавычек `"""`. Сам уровень отступа кавычек всегда совпадает с уровнем отступа ключевого слова `def` или `class`.
4. **Разделение секций:** Между логическими блоками параметров (`Args/Parameters`, `Returns`, `Raises`) **всегда вставляется одна пустая строка**.

### 1. Документирование ФУНКЦИЙ

В функциях критически важно документировать: **входные аргументы (Args/Parameters)**, **возвращаемое значение (Returns)** и **возможные исключения (Raises)**.

#### Вариант А: Google Style (Рекомендуется для большинства веб- и backend-проектов)
```python
def calculate_discount(price: float, discount: float) -> float:
    """Вычисляет итоговую стоимость товара с учетом скидки.

    Args:
        price (float): Исходная стоимость товара (должна быть > 0).
        discount (float): Процент скидки в диапазоне от 0.0 до 1.0.

    Returns:
        float: Итоговая стоимость после применения скидки.

    Raises:
        ValueError: Если цена отрицательная или скидка вне диапазона.
    """
    if price < 0 or not (0.0 <= discount <= 1.0):
        raise ValueError("Некорректные входные данные")
    return price * (1.0 - discount)
```

#### Вариант Б: NumPy Style (Часто используется в Data Science и математических библиотеках)
```python
def calculate_discount(price, discount):
    """Вычисляет итоговую стоимость товара с учетом скидки.

    Parameters
    ----------
    price : float
        Исходная стоимость товара (должна быть > 0).
    discount : float
        Процент скидки в диапазоне от 0.0 до 1.0.

    Returns
    -------
    float
        Итоговая стоимость после применения скидки.

    Raises
    ------
    ValueError
        Если цена отрицательная или скидка вне диапазона.
    """
    if price < 0 or not (0.0 <= discount <= 1.0):
        raise ValueError("Некорректные входные данные")
    return price * (1.0 - discount)
```

### 2. Документирование КЛАССОВ

Для классов принято документировать сам класс (его общее назначение) и его **публичные свойства (Attributes)**.

*Важный канон (PEP 257):* Документацию для метода `__init__` (конструктора) принято писать **внутри docstring самого класса**, а не внутри метода `__init__`.

#### Вариант А: Google Style
```python
class Product:
    """Представляет товар в каталоге интернет-магазина.

    Attributes:
        id (int): Уникальный идентификатор товара.
        name (str): Название товара.
        stock (int): Количество единиц товара на складе.
    """

    def __init__(self, product_id: int, name: str, stock: int = 0):
        self.id = product_id
        self.name = name
        self.stock = stock
```

#### Вариант Б: NumPy Style
```python
class Product:
    """Представляет товар в каталоге интернет-магазина.

    Attributes
    ----------
    id : int
        Уникальный идентификатор товара.
    name : str
        Название товара.
    stock : int
        Количество единиц товара на складе.
    """

    def __init__(self, product_id, name, stock=0):
        self.id = product_id
        self.name = name
        self.stock = stock
```

### Сводное сравнение: что выбрать?

| Критерий            | Google Style                             | NumPy Style                                  |
| :------------------ | :--------------------------------------- | :------------------------------------------- |
| **Компактность**    | Высокая (занимает меньше строк в файле). | Низкая (много пустых строк и подчеркиваний). |
| **Читаемость**      | Отличная для обычного веб-кода и API.    | Отличная для сложных математических функций. |
| **Сфера применения**| Скрипты, веб-разработка, backend.        | Data Science, Machine Learning, статистика.  |

### 3. Docstrings для ПАКЕТОВ (Packages)

Пакет в Python — это папка с модулями, которая содержит файл `__init__.py`. Документировать пакет нужно именно внутри этого файла.

### Каноны оформления

1. **Расположение:** Строка документации должна быть **самой первой строкой** в файле `__init__.py`.
2. **Назначение:** Описать общую цель пакета, перечислить основные экспортируемые модули, подпакеты или предоставить быстрый пример использования.
3. **Содержимое секции `Modules` / `Subpackages`:** Краткое имя модуля и его назначение (в одну строку).

---

### Примеры оформления

#### Вариант А: Google Style (Компактный)
```python
"""Инструменты для обработки и валидации платежей.

Этот пакет предоставляет унифицированный интерфейс для интеграции
с различными платежными шлюзами (Stripe, PayPal).

Modules:
    client: Клиент для отправки HTTP-запросов к API шлюзов.
    exceptions: Кастомные ошибки валидации и проведения транзакций.
    models: Схемы данных для платежей и чеков.
"""
```

#### Вариант Б: NumPy Style (Для крупных пакетов)
```python
"""Инструменты для обработки и валидации платежей.

"""
```
